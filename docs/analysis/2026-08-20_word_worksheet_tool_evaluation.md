# 評估建議書：「筆順合併自動插圖作業單產生器」× stroke_order

日期：2026-08-20｜參考對象：同好開發的 Windows 小程式（整合於「國字語詞
語音學習系統」，服務讀寫障礙學生）——輸入生字列表 → 自動抓筆順字典
（twpen.com）的**筆順分解圖** → 自動搜尋網路相關**插圖** → 一併貼進
**Word 作業單**。
本專案：stroke_order（v0.14.291）

素材取得情形（誠實標注）：Facebook 社團貼文、Notion 教材製作說明（需 JS）、
SharePoint 下載點（需登入）三者無法直接抓取；本文依據使用者轉述全文、
weebly 系統主頁與 twpen.com 可公開查得的內容寫成。**未實際跑過該程式**，
「做法解讀」為合理反推，若日後取得程式可覆核。

## 0. 摘要（一段話版）

**這是第四份借鏡，也是第一份「田野證據」**——它不是功能靈感，而是直接告訴
我們老師實際的工作流：**生字列表 → 筆順分解圖 ＋ 每字插圖 → Word 檔**。
上一段收工的待辦第一條正是 W0（看老師實際怎麼用），這份分享等於把 W0 的
一半答案送上門了。對照下來三個發現：

1. **老師貼的不是描紅格，是「筆順分解圖」**（第1筆、第1-2筆、…的靜態累積
   序列，twpen 那種）——本專案有完整逐筆資料、GIF 端有現成的累積 frame
   邏輯，但**沒有任何一個列印用的靜態分解圖輸出**。資料在、沒排（同 W2
   之前的釋義）。
2. **老師的終點站是 Word，不是瀏覽器**——他們要在作業單裡混排自己的內容。
   本專案出 SVG/PDF/PNG/G-code，可印不可編。
3. **「自動搜尋網路插圖」我們不該學**——版權風險（該工具直接貼網路圖片
   進 Word），且 T3 已量過官方插圖覆蓋率（最高頻 500 字僅 22.4%）並定案
   「老師自備上傳槽」。這裡的正解是把「插圖位」留出來，不是把圖抓進來。

反過來值得說白的差異點：老師去 twpen 抓圖的**原因是「省下購買筆順字型的
錢」**——本專案的筆順渲染是原生的（g0v 教育部標準楷書筆順，離線部署），
根本不需要字型也不需要抓圖。我們缺的只是把它排成老師要的**那種紙**。

## 1. 它的做法解讀（從轉述反推）

輸入生字列表 → 逐字向 twpen.com 取筆順分解圖（推測為網頁截圖或圖檔抓取）
→ 逐字網路圖片搜尋、取相關插圖 → 用 Office 自動化把兩者依序貼入 Word 作業
單。搭配的母系統（國字語詞語音學習系統）另有注音、識字、書寫、語詞、句型
與語音念讀，教材可由老師自編或由書商「大補帖」轉檔。

**強項**：(a) 精準命中老師工作流的終點格式（Word，可再編輯）；(b) 插圖
幫助讀寫障礙學生「理解並念讀正在書寫的字」——插圖不是裝飾，是無障礙需求；
(c) 全自動批次，省下逐字複製貼上。

**弱項／風險**：(a) 筆順圖來自抓取 twpen——該站字詞資料為《重編國語辭典
修訂本》CC BY-ND 3.0 TW，圖形呈現的再散布地位不明，抓取管道也可能隨網站
改版斷裂；(b) **網路圖片搜尋直接貼入**——版權狀態完全不可控，教材若再
散布有實質風險；(c) Windows＋Office 相依，非 Windows 環境無法用。

## 3. 缺口一（X1）：筆順分解圖——老師真正在貼的東西

**現況**：`/teach` 有逐筆動畫、`/api/*.gif` 有累積 frame 動圖，但**印在紙上
的靜態分解圖一個都沒有**。老師要的是 twpen 那種「一字一列、第 N 格畫到第
N 筆、當前筆畫醒目」的圖。

**我們的地基**：`Character.strokes` 天生有序；「畫到第 N 筆、之前的淡、
當前的深」正是 gif.py 每一 frame 在做的事，改成並排輸出 SVG 即可。格線、
縮放、多頁貼紙（W1 `fit_svg_to_paper`）全部現成。

**授權**：筆順資料是 g0v/zh-stroke-data（教育部標準楷書），本專案既有授權
聲明已涵蓋，**不新增任何授權面**——這正是對 twpen 抓圖路線的根本優勢。

**風險註記（§97：預繳的守門規格）**：
- 分解圖格數＝筆畫數，30 畫的字一列爆版——**分解圖必須自動換列，且格數
  上限要與版面寬度解耦**（同 §96.1 教訓：尺寸相對於最後決定大小的那層）。
- 「當前筆醒目」的顏色若只靠彩色，黑白影印後消失——**醒目手段必須在灰階
  下仍可辨**（讀寫障礙場景幾乎必然黑白影印）。

## 4. 缺口二（X2）：docx 出口——老師的終點站

**現況**：PDF 解決「印」，解決不了「編」。老師要把筆順圖、插圖、自己的
評量題混排在同一份作業單——那是 Word 的主場，也是這支借鏡工具存在的
全部理由。

**可行路徑**：`python-docx` 1.2.0（**MIT**，相依 lxml＋typing_extensions
——lxml 是新增的傳遞相依，wheel 約 5 MB）。管線：既有 SVG →(cairosvg，
已有) PNG → 逐字插入 docx 表格。W1 的記憶體配額模型直接沿用（同樣是
光柵化，§94：先量再定介面）。

**風險註記（§97）**：
- **docx 內嵌的是點陣圖**，放大會糊——dpi 要跟 W1 一樣可設、受配額自動
  下修、並用誠實標頭回報實際採用值。
- 新相依 → **可降級**：python-docx 缺席時 503＋訊息說明既有 PDF 出口仍
  可用（同 segno 模式：相依缺席回 503 不是 500）。
- 內嵌圖的 docx 檔案大小 ≈ 頁數 × 張數 × dpi——**要量測後定預設 dpi**，
  不能沿用 PDF 的 150 直覺（Word 檔會被 email 寄，太大寄不出去）。

## 5. 設計分歧（X3）：插圖——學「留位」，不學「抓圖」

該工具自動搜尋網路圖片貼入——對個別老師自用可行，對本專案是不能踩的線
（版權不可控，且我們的產出會被再散布）。既有事實：

- T3 已量過官方插圖覆蓋率：最高頻 500 字 22.4%、全字表 12%——「約五個常教
  的字命中一個」，不打包的決策數據仍成立，本次不翻案。
- T3 已有老師自備插圖槽（data URL 內嵌、離線可開）。

**這裡該做的**是在 X1/X2 的作業單版面裡**留出固定插圖位**（空框＋「請貼上
圖片」提示），老師在 Word 裡自己貼——把他工具流程裡「自動但危險」的一步，
換成「手動但乾淨」的一步，且正好落在老師本來就會編輯的 Word 檔裡。零成本
（版面規劃而已）、零授權面。

## 6. W0 田野證據歸檔

這份分享回答了 W0 的一半：**老師的工作流終點是 Word；核心物件是筆順分解圖
＋插圖；動機是省字型錢**。尚未回答的另一半：我們既有的 `/teach` 與字帖
（PDF 直印路線）對這群老師是否「夠用」到不需要 Word——這要等實際回饋，
X2 的優先序因此保留了下修空間（見 §7）。

## 7. QODA 選項

### 選項 X1：筆順分解圖（靜態逐筆累積，SVG/PDF/PNG）★ 推薦當第一輪

- **成本**：低–中。資料與累積邏輯全在，新排版器＋接 W1 出口。
- **風險**：換列版面（§96 教訓在前）；灰階可辨。
- **價值**：老師從 twpen 抓圖的**替代品本體**；不論 Word 做不做都有用
  （PDF 直印、或日後插進 docx）。

### 選項 X2：docx 出口（作業單含筆順分解圖＋描紅格＋插圖留位）

- **成本**：中。新相依 python-docx（MIT）＋版面組裝＋配額沿用。
- **風險**：檔案大小要量測；相依可降級；點陣圖 dpi 誠實回報。
- **價值**：進老師的主場。**但建議等 X1 落地＋W0 回饋再定**——如果 PDF
  直印已滿足多數人，docx 的邊際價值會比現在看起來小。

### 選項 X3：插圖留位（併入 X1/X2 的版面規則，不獨立成輪）

- **成本**：趨近零。**明確不做**：自動抓網路圖片。

### 選項 X0：只歸檔

三個缺口都不動，把本文當 W0 證據，等更多老師回饋。

---

## 8. 優先序建議

**X1 →（W0 回饋）→ X2；X3 併入版面規則；本輪不翻案 T3。**

理由：X1 是他整條流程的核心物件，我們做出來是「原生且授權乾淨」對「抓取
且授權模糊」的直接替代，成本又最低；X2 動相依與檔案大小兩個要量測的面，
且其必要性正是 W0 要驗證的問題——讓證據先回來。每輪獨立可用（§90）：X1
出去就能印，不必等 X2。
