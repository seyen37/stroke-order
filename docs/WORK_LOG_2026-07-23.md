## 機構弧：從「逐筆 tab」誤讀到「鏤空箱型」定案

使用者要「立體字卡片」——打字後生出可折立的鏤空字 pop-up 賀卡。我一開始照
**想像的機構**寫：把文字頂連接頂面的部分，拆成每個筆畫各一個小長方形 tab
（參考 DAD 立體卡範本），反覆多輪。使用者連續回「差異太大，根本不理解我的
修改」——這是明確的停損訊號，我卻又多繞了幾輪才真正回到原點。

**轉折**：使用者給了**實體折好的箱型照片**（「快樂」折成一個立體箱）。正確機構
其實最簡：

- **前立面**＝整片鏤空文字（字即結構、字身是材料、周圍透空剪掉）。
- **文字頂**＝一條摺線，往後折接**頂面 roof**。
- **文字底**＝一條摺線，往下折接**底座**。
- **字中一條中線谷折**穿過文字中段，卡片才能平整折合。
- 對稱：|字頂到中線|＝|字底到中線|（|a-d|=|b-c|），對稱才折得平。

**沒有 per-stroke tab**。我先前把「文字頂整條摺線」誤讀成「每個筆畫各一個 tab」，
把最簡的一條摺線複雜化成 N 個長方形——這是把紙上想像當成機構的典型錯。使用者
確認「這個鏤空箱型對了」後，雙層（兩箱疊成階梯、中線穿中間 tread 正中、上下兩排
等高對稱）也實體站得好，才進網頁模式。

**教訓**：紙藝／實體機構要**先折一個實體原型定案，再寫幾何**。程式碼描述的是
「摺起來會立起來」的實體行為，紙上想像最容易把簡單摺線複雜化；誤讀使用者修改時，
回到最簡機構（Occam）比堆疊特例更可能對。→ PRINCIPLES §68。

## 缺字型測試 skip 修復＋守門

首次跑收工檢查.bat 時 6 個 popup 測試 FAILED——`CharacterNotFound：思源黑體
未安裝`。

**根因**：`NotoSansTC-Bold.otf` **不進版控**、由 `scripts/render_fetch_fonts.sh`
於 Render 部署時抓；開發機（本裝置 `~/.stroke-order/hei-fonts/`）沒放就缺。這是
**部署期字型相依**，不是功能壞。

**修法**：需字型的測試沿用既有 `noto_hei` 那套守門——
`needs_hei = pytest.mark.skipif(not default_hei_font_path().exists())`，缺字型時
**skip 不是 fail**；不需字型的測試（`_label`/`_label_runs` 計數、頁面 200、空字/
超長 422）不掛守門獨立驗。端點缺字型回 **503 帶安裝指引**。再驗：有字型 8 過、
無字型 2 過 6 skip，零 failure。→ PRINCIPLES §68 姊妹律。

**路由快照**：刻意新增 `/popup`、`/api/popup/svg` 兩路由，同步更新
`test_route_snapshot.py` 的 ROUTE_SNAPSHOT（承既有「增刪路由先改快照」紀律）。

## 5fv：統一出口信封（v0.14.271，`4170364`）——B 案的成本翻案

B 案原估「動 11 個模式匯出、3 輪以上」。開工盤點發現兩個**單一出口 choke
point**：`svg_response`（W3 重構收斂的「全站唯一 image/svg+xml 出口」）與
`render_pages_as_single_or_zip`（文字群五模式共用的多頁出口）——在這兩點內嵌
＋逐呼叫點標 mode，11 個模式**一輪**接完；唯一前端產 SVG 的禪繞（exporters.mjs
pathsToSvg）單獨補。**估工前先盤 choke point，成本差三倍。**→ §75。

- `exporters/envelope.py`：一套 `stroke-order-export-v1` 信封蓋全模式（不做
  per-mode schema）——embed/parse、冪等、決定性輸出（無時間戳利 dedup）、
  CDATA `]]>` 轉義防注入。
- 14 個呼叫點標 mode（notebook/letter/manuscript/grid/stencil/single/sutra/
  wordart/doodle/patch/stamp）；zip 逐頁嵌；mandala/popup 既有 schema 不動。
- 守門回歸鎖（§70 掃全類）：routes 層 `svg_response(` 必帶 `mode=`、多頁打包
  必帶 `envelope_mode=`（括號配對掃描＋白名單例外制）——未來新端點漏嵌直接紅燈。
- tests 1870→1893；部署驗收：grid/patch/wordart 信封＋前端模組全 PASS。

## 5fz：Brevo HTTP API 寄信（v0.14.275，`ad0db54`）——部署平台雙關卡事故

使用者設好 Gmail SMTP 後 request-login 500、log 出
`OSError [Errno 101] Network is unreachable`。**查證（web search 官方
changelog）**：Render 免費層封鎖所有對外 SMTP 埠（25/465/587）——換任何 SMTP
帳號都不通，唯一通道是走 HTTPS 443 的郵件 API。**先查平台限制文件，再懷疑
設定。**→ §80。

- smtp.py 三模式（優先序）：dev mode ＞ **Brevo HTTP API（新）** ＞ SMTP
  fallback。stdlib urllib 零新依賴；寄件人沿用 `SMTP_FROM`（須 Brevo 驗證）；
  錯誤誠實上拋（HTTP 狀態碼＋常見原因＋回應摘要）。
- 選型：Brevo（免費 300 封/日、**驗證單一寄件人即可寄任意收件人、不需自有
  網域**）勝 Resend（寄任意收件人需自有網域——本站掛 onrender.com 下沒有）。
- **第二關**：Brevo 回 401 unrecognised IP——使用者帳號開著「授權 IP 白名單」。
  新版錯誤訊息把 Brevo 回應原文帶出來，**一眼定位病因**（錯誤訊息投資當場
  回本）。解法：把 Render 兩段共用出口網段（74.220.52.0/24、74.220.60.0/24）
  加入授權清單。→ §80。
- 維運鏈端到端實測（使用者確認）：dev mode 撿 log 連結登入→管理端全數出現
  （GALLERY_ADMIN_EMAILS 生效）→關 dev mode→**「寄出連結」信真的進信箱→
  點連結登入成功**。
- tests 1967→1976（全 monkeypatch 不打網路；asyncio.run 每測試全新 loop）。
- docs/GALLERY_DEPLOYMENT.md 新增「情境 0：Render 免費層必讀」。
