# 決策紀錄 2026-08-20（R1b）：字重滑桿——落點盤查與可變字體軸

對應 PRINCIPLES §92（**「該加什麼旋鈕」要先盤落點再選，落點不是唯一的**；
提選項前先掃既有實作，不要把已存在的東西當新方案；正規化比值只是幾何的
一半，方向與巢狀是另一半）。承 §35–§38（雲端資源天花板）、§76（單一事實源）、
§89（下結論前覆查數字）、§91（S1 感受型需求先量測）。版本 0.14.287。

---

## 整體脈絡

S1 的前置量測得到一個結論：「昭源環方看著舒服」的真因是筆畫細，所以
**該開的旋鈕是字重不是圓角**。R1b 就是把那個結論做出來。但「開字重旋鈕」
只指出了方向，沒指出**接在哪**——本輪一半的工作是盤落點。

## 決策 1：字重滑桿接在可變字體軸，不接在另外兩個看似更近的落點

**Question**：專案裡有三個地方「看起來」可以放字重旋鈕，哪個真的可用？

**量測（三個落點各自的天花板）**：

| 落點 | 對哪些字源有效 | 可調範圍（實測） | 致命限制 |
|---|---|---|---|
| 真輪廓 ±δ 形態學 | 全部七種 | 安全區 ±20 EM ≈ **筆寬 ±9%** | 有感的範圍（+40）就填洞黏部件；痛點方向（加粗）恰好是危險方向 |
| `skeleton_glyph.weight`（R1a 現成） | 骨架長肉 | 大 | g0v bundle 只有 **1,827 字**，常用 808 字表僅命中 **65%**；且目前只在思源黑體缺字時走到 |
| **可變字體 `wght` 軸** | 昭源環方 | **筆寬 18→48 px（2.7 倍）** | 只有這一顆字型有 VF；載入時 RSS +75 MB |

真輪廓 ±δ 的量測（「國/歡/明」、50 mm 字框）：δ=+40 時「歡」墨連通件
4→1、洞 4→5，「國」洞 2→5。δ=−40 時圓體「國」的字碗被咬破（洞 2→1）。

**選項**：A ±δ（廣但無力）／B 骨架長肉（強但覆蓋不足）／★ C 可變字體軸／
D 撤下 R1b。

**選擇**：☑ C（使用者 sign-off）。理由：唯一「調得動又不破字」的落點，
而且它給的是**字型設計師逐級調好的字重**，不是把輪廓做形態學膨脹的後製。

**訂正（§89）**：提選項時我把 ±δ 描述成「還沒有的東西」——**錯**。
`/api/stencil` 早有 `bold_mm`（0–5 mm、`_dilate` 光柵膨脹），前端也有
`#sc-bold`。它就是 ±δ 的加粗半邊。提選項前沒掃既有實作，數據是真的但
選項描述失真。已在 UI tooltip 與 API description 把兩者語意分清楚：
**字重＝字型本身的粗細；加粗＝事後膨脹濾鏡**，兩者並存不互斥。

## 決策 2：雙軌記憶體——預設走靜態檔，拉滑桿才載可變字體

**Question**：VF 首次取字 217 ms、RSS +75 MB（之後每字約 1 ms、RSS 不再長）。
Render 免費層 512 MB，§35–§38 才因 OOM 付過代價。

**選項**：★ A 雙軌（預設靜態 700B，給 weight 才開 VF）／B 只留 VF（部署少
一個檔、程式碼單一路徑，但每次用昭源環方都付 +75 MB）／C env 旗標本機開、
線上停用。

**選擇**：☑ A（使用者 sign-off）。**現有使用者的行為與記憶體足跡零變動**，
成本只由主動調字重的請求承擔。部署多抓一個 21.7 MB 的檔，可接受。

**鎖成測試**（沒有這兩條，「雙軌」只是註解裡的宣稱）：

- `test_r1b_no_weight_output_is_bit_identical_to_before`：不給 weight 的
  輸出逐點等同 R1b 之前的靜態路徑。
- `test_r1b_no_weight_never_opens_the_variable_font`：把 VF 路徑指到不存在
  的檔，靜態路徑仍須完全正常，且 `src._vf is None`。哪天有人把 VF 提到
  `__init__` 預載，這條立刻紅。

## 決策 3：夾限 300–800，不開放上游 fvar 的全域 200–900

**量測**（「國」、50 mm 字框、2 mm 連筋，已套重疊補正）：

| wght | 筆寬 px | 墨連通件 | 殘腔 |
|---|---|---|---|
| 200 | 12.0 | 5 | 0 |
| 250 | 16.0 | 5 | 0 |
| **300** | 18.0 | 5 | 0 |
| 500 | 34.0 | 5 | 0 |
| 700 | 42.5 | 3 | 0 |
| **800** | 48.0 | 3 | 0 |
| 850 | 50.0 | 2 | 0 |
| 900 | 52.0 | 2 | 0 |

殘腔全程 0（任何字重都是物理有效字模），字碗洞數在 300–800 完全穩定
（國 2、歡 5、明 4——加粗不會把字碗填死）。夾限依據：

- **下界 300**：再細就低於 18 px；200 只有 12 px，等比縮到小尺寸餘裕不足
  （同 S1 選 700B 而非 400R 的理由，同一條標準用兩次）。
- **上界 800**：850 起「國」墨連通件掉到 2，**比我們已經在出貨的靜態 700B
  （3 件）更黏**。以出貨中的東西當基準線，不用理論值。

夾限只有一份數字：`sources/chiron_round.WEIGHT_MIN/MAX`，API 的 `Query`
`ge/le` 與 UI 滑桿的 `min/max` 都由它推導，並由
`test_r1b_slider_range_matches_backend_clamp` 鎖住。

## 決策 4：可變字體的重疊輪廓必須補正（實作中發現的 bug）

**觸發**：接完管線做煙霧測試，發現 VF@700 與靜態 700B 輪廓數不符（5 vs 9）。

**根因**：字型的填充規則是 **nonzero**；靜態字重檔在建置時做過 overlap
removal，所以拿 even-odd 畫也對。但**重疊消除的結果無法沿 wght 軸內插**，
可變字體因此保留重疊輪廓。本專案下游是 even-odd，重疊處被挖成假洞：

| 字 | 洞數（靜態→VF 未補正） | 墨面積差 |
|---|---|---|
| 明 | 4 → 10 | −6.2% |
| 國 | 2 → 5 | −4.4% |
| 歡 | 4 → 14 | −11.6% |
| 永 | 0 → 2 | −7.6% |

**三次才做對，每次都是量出來才知道錯**（過程留著，因為錯法本身有價值）：

1. **只看方向、批次做**「外環聯集 − 洞環聯集」→ 巢狀字爆掉。「田」是口的
   洞裡再放十，一次性差集把十整個扣掉（面積 −33%、洞 4→1）。
   *（這一版還順帶寫錯了方向判定：Y-down 座標下外環是負面積，我照教科書
   寫成正的。改成「面積最大的環必為外環，以它的方向為準」——不寫死慣例，
   日後翻座標系也不會壞。）*
2. **只看巢狀深度、不看方向** → 落在別的筆畫內部的重疊筆畫被誤判成洞而
   扣掉（「歡」−29%、「鬱」−15%、「書」−25%）。
3. **✔ 方向決定聯集/差集，但依面積遞減逐環套用**（不批次）。父環必先於
   子環處理，十因此在洞被挖掉之後才聯集回去；同向重疊的筆畫落進聯集、
   自然被吸收。

**驗收**：22 字比對，20 字墨面積與靜態檔差 <0.5%；剩 2 字（快、囊）拓撲
件數差 1 但面積差也 <0.5%——是「剛好相切」處的次像素差異（靜態檔做過
overlap removal 會把相切處併掉），非幾何錯誤。故
`test_r1b_vf_at_static_weight_matches_the_static_file` **鎖墨面積 ±2%
而不鎖拓撲件數**——鎖不變式，不鎖實作巧合（承 §66）。

補正只掛在 weight 路徑（`resolve_overlaps` 是字源自己的靜態方法，管線只問
「這個字源有沒有要補正的東西」），靜態路徑完全不經過，故零回歸。shapely
缺席時原樣回傳、不假裝成功（§8）。成本：快取後單字 <10 ms。
