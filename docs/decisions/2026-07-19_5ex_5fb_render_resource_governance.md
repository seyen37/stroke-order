# 5ex～5fb 渲染資源治理鏈：QODA 重放（免費層 512MB／0.1 vCPU 下的篆書渲染）

- **日期**：2026-07-19（第四階段）
- **版本**：0.14.239 → 0.14.244（dc28ac9→400d2fb→aeaab5e→131be86→77514da）
- **對應原則**：§50–§52
- **狀態**：0.14.241/242/243 線上驗收 PASS；0.14.244 驗收排程中

## 背景

使用者實機：篆書預覽久等、連按崩潰、週期表×篆體必殺；後續心經×
篆書進度條一半 502。Render 免費層 512MB／~0.1 vCPU。

## 量測先行（每輪都先量再開藥）

- 5ex：冷 ×3 併發 RSS 峰值 486MB／渲染後停 471MB（代理字型上界）。
- 5fb：tracemalloc top-stats 逐層切割——TTFont 開銷是**首字即付**
  （檔案緩衝 23MB＋hmtx 21MB＋CFF 9MB／肥字型）**非逐字累積**；
  自家字形快取實測 63KB/字。**推翻「209MB 棘輪」初判、改判藥方**
  （若照初判做「更激進的逐字回收」＝白工＋重開銷）。

## 治理鏈六件套（QODA 逐輪定案）

1. **快取（治重複）**：預覽 GET 化（A1 vs POST body-hash——GET 端點
   參數本就齊全，補 glyph_chars 一參即進 5eu 快取；重複預覽 0.003s）。
2. **閘門（鎖峰值）**：asyncio.Semaphore(2) 排隊不拒絕（vs 429——
   對使用者透明）；快取命中不過閘；/capacity 豁免（打字回饋不凍）。
3. **中止（斷殭屍）**：AbortController 起手 abort 舊輪；世代計數
   只防誤塞畫面、abort 才停得住伺服器上燒資源的舊請求。
4. **分段（攤前期）**：body＋table 頁空白先出＋分批填字；自繪多字
   表格偵測無 cellmap 回退一次性。
5. **回收（壓底線）**：LRU 384（63KB/字 → ~24MB/源）＋閘門歸零時
   gc＋malloc_trim（471→329MB）＋TTFont 句柄回收（每 48 字形丟
   句柄不 close——在途舊句柄由 GC 收；cmap/度量自快取跨句柄重用）。
6. **縮批＋重試（抗逾時）**：篆/隸單批 12→6（骨架化時長砍半）＋
   單批失敗 1.5s 後重試一次（AbortError 不重試）——502 同症有兩因
   （OOM／路由逾時），此件套治後者。

## 附帶根因修

opencc 初始化 race：兩顆轉換器、guard 變數先發布→他緒空窗拿到
半成品（s2t=None）→500。修法＝局部建好、guard 最後發布；慢速
OpenCC 注入回歸測試重現空窗。**併發測試的附加價值：閘門 E2E 當場
揪出這顆與 grid.py d="Z"（5ew-R4）兩個既有 bug。**

## 測試方法學（§50 的素材）

- TestClient 每請求各開事件迴圈→跨迴圈搶同一 asyncio.Semaphore
  死鎖；併發測試改 httpx.ASGITransport＋單迴圈 asyncio.gather。
- E2E 等 boot 安定（迴向偈非同步填入→快取 key 漂移＝假陰性）。
- 瀏覽器 HTTP 快取遮蔽 x-render-cache 觀察——page.route 攔截停用。
- 巢狀 SVG 數 children 用 DOM 解析、不用正則。
- fontTools 裁「有部件無目標字」子集字型＝可控模擬字型缺字
  （沙箱 Noto、nuc11 msjh，無字型 skip）。
