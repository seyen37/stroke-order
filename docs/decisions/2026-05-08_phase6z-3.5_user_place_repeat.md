## 2. 架構轉換

### 2.1 從 grid auto-fill → 點選 place + repeat

| 6z-3 (auto-fill) | **6z-3.5 (user-place)** |
|---|---|
| `drawTangleLayer` 呼叫 `buildTangle(key, area, density)` 鋪滿 grid | iterate `_placedUnits` → 對每個 unit 呼叫 `TANGLES[].buildUnit(cx, cy, scale)` |
| 點 radio 即見 grid auto-fill 整片 | 點 radio 後**不畫**、user click canvas 才放第一單元 |
| 圖案是「**已畫好的禪繞**」 觀感 | 圖案是「**user 親手畫**」 觀感 (acquisition power 啟動) |
| Mode 視覺差異 (pure/hollow/bg) 對 grid 無感 | 同 mode 設計沿用 (clip evenodd 仍處理 nested contour) |

### 2.2 Coord transform — viewport ↔ tile-local

Click event 在 viewport (canvas px) coords，但 `_placedUnits` 存 tile-local coords (so rotation + pan 自動 inherit)。需 inverse forward transform：

```
Forward: M = T(pan) · T(c) · R(θ) · T(-c)
         x_view = pan + c + R(θ)(p_tile - c)
Inverse: p_tile = c + R(-θ)(x_view - pan - c)
```

`viewportToTileLocal(viewX, viewY)` helper 套上述公式 + `getBoundingClientRect()` 處理 CSS scaling (canvas internal vs displayed)。

### 2.3 Direction state machine

```
初始: _placedUnits = [], _lastDirection = null
click 1: _placedUnits = [A], _lastDirection 不變 (null)
click 2: _placedUnits = [A, B], _lastDirection = (B - A)
click 3: _placedUnits = [A, B, C], _lastDirection = (C - B)
R 鍵 (REPEAT_3 ACTION): _placedUnits push C+dir, C+2dir, C+3dir
```

對位 v0.3 §1 主流程 R1「疊加 3 次」 落實。

## 5. P7-COMPLETION

- **任務**：6z-3 auto-fill grid → user-place + repeat
- **方案**：
  - tangle.mjs 加 `buildUnit` (single-unit) export，`TANGLES[].buildUnit` registry
  - zentangle.js 加 `_placedUnits` array + `viewportToTileLocal` inverse transform
  - canvas left-click handler + R 鍵 ACTION handler + clear button
  - `drawTangleLayer` 改 iterate placed units (取代 grid auto-fill)
- **改動**：4 files (3 mod + 1 new doc) + 1 test mod, ~+200 / -40 lines
- **影響分析**：
  - 既有 `buildTangle(key, area, density)` grid 函數**未刪**、可作 6z-3.5.X auto-fill fallback / preview thumbnail
  - `withTileRotation` ctx transform 不變、placed units 自動 inherit rotation + pan
  - clip("evenodd") nested contour mask 不變、placed units 仍受 outline 限制
  - ACTIONS dispatcher registry (6z-2c 升級) 持續 work：repeat-3 / repeat-fill 接 handler
  - 50 + 18 + 13 全 pass, 無 regression
- **三問自審**：
  - 方案正確：是。User-place 對齊 v0.3 §1 主流程 thesis；Inverse transform 是正確的 viewport→tile-local 數學
  - 影響全面：是。Grep 既有 `buildTangle` 唯一 caller 是 drawTangleLayer 已改；button click handler 沒 conflict (canvas 之前無 left-click listener)
  - 回歸風險：低。Auto-fill grid 函數仍 export + Node tested；新加層 (placed units) 在既有架構 stack 之上
- **剩餘風險**：
  1. **Click on rotated canvas inverse transform 視覺正確性待 user verify** — 旋轉 45° 點字框邊角，click 應該落在字框邊角 tile-local px
  2. **R 鍵 in INPUT field 衝突** — 6z-1E `wireInputScaffolding` 已 guard `if tag === INPUT/SELECT/TEXTAREA return`、不在 input 中 hijack，安全
  3. **無 click outside outline 的檢測** — 點 canvas 但不在 outline 內、unit 仍會 push 但被 clip 切掉視覺；user 體驗會像「點不到」 — 6z-3.5.X 補：點外側時 status 提示「請在字內點」
  4. **R 鍵 repeat 沒 direction 時 status warn** — 已實作；user 第一次按 R 會看到「需要至少 2 個 unit」 提示
  5. **Direction 計算用 last 2 units，user 切換 tangle 後仍延續舊 direction** — 是 feature (user 可能想沿同一方向放不同 tangle) 不是 bug；如反直覺 6z-3.5.X 補 reset

## 7. 經驗萃取（candidate）

> **User-driven 創作 vs. auto-fill — acquisition power 來自 user 親手放，不是 click-and-fill**
>
> Auto-fill 是「**結果展示**」，user-place 是「**創作體驗**」。Creative tool 的 acquisition core 在後者，前者是 demo / preview。
> 6z-3 MVP 用 auto-fill 驗 dispatch + clip 架構是合理 stepping stone，但 final UX 必走 user-place。
> User catch 「目前看起來是自動填滿」 是直擊架構問題、不是 polish 問題。
