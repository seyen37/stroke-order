## 1. 問題本質

600×600 canvas 在 45° 旋轉下，bbox 變 ~849×849px，**對角溢出 ~124 px** 在 4 側。User 看不到旋轉後的字角細節 → acquisition 體驗扣分。

數學：對 ts × ts 方形旋轉 θ：
```
bboxExt   = ts · (|cos θ| + |sin θ|)
overflow  = (bboxExt − ts) / 2  (per side)
```
- θ=0° → 0
- θ=45° → ts·(√2−1)/2 ≈ 0.207·ts (600px → 124px)

---

## 2. 解：4 側 pan button (toggle 行為)

### 2.1 State machine

`_panState ∈ {center, top, bottom, left, right}` (per-session, 不 persist)：
- 初始 = `"center"`
- Click 同側 → 回 `"center"`
- Click 異側 → 切到該側

### 2.2 Pan vector

```js
function computePanOffset() {
  const v = rotationOverflow();
  switch (_panState) {
    case "top":    return [0,  v];   // 紙磚 DOWN → 露出原本 top 超界
    case "bottom": return [0, -v];
    case "left":   return [ v, 0];
    case "right":  return [-v, 0];
    default:       return [0, 0];
  }
}
```

### 2.3 ctx transform 升級

`withTileRotation` 加 `ctx.translate(panX, panY)` 在 rotation 之前（concat 順序末段）：
```js
ctx.translate(px, py);     // 6z-2.2 pan
ctx.translate(cx, cy);     // 6z-2.1 rotation pivot
ctx.rotate(...);
ctx.translate(-cx, -cy);
```
數學上 `M = T(pan) · T(c) · R(θ) · T(-c)`，對任一點 p → `pan + c + R(θ)(p−c)` = 旋轉後再 shift by pan。

### 2.4 UI 設計

CSS grid 3×3 包 canvas：
```
.  ↑上 .
←左 [canvas] →右
.  ↓下 .
```
`writing-mode: vertical-lr` 讓左/右 button 文字直寫、與上下對稱。

Active button 用 `--accent` 紅色高亮、color 反白、border 加粗。

## 5. P7-COMPLETION

- **任務**：旋轉超界 → 4 側 pan button 露出超界區（toggle 行為）
- **方案**：`_panState` per-session enum + `rotationOverflow` 純數學 + ctx.translate 加進 transform chain（pan + rotation 複合）
- **改動**：3 files (index.html / zentangle.js / pyproject.toml) + 1 new doc, +107 / -3 lines
- **影響分析**：
  - `withTileRotation` 早期 short-circuit 仍 work：當 rot=0 且 pan=center → fn() 直接執行
  - 既有 8 preset / slider / 立即回正 / 上次角度 全不變
  - tile size resize / char/source change 流程不變（pan state 是獨立 dimension）
  - `ROTATION_HISTORY` 跟 pan 不互相干涉
  - 33 既有測試 + 11 smoke 全 pass、無 regression
- **三問自審**：
  - 方案正確：是。Pan amount = 數學上完整露出超界區、單按一次到位、再按回中心
  - 影響全面：是。grep `_panState` 確認所有 redrawAll 路徑都 derive pan offset
  - 回歸風險：低。新加維度 (pan)，預設 "center" 等於零行為；既有 25 Node + 18 pytest 全 pass
- **剩餘風險**：
  1. **rot=0 時 pan 按鈕點了沒效果** — `rotationOverflow()` 回 0 → `computePanOffset` 回 [0,0]。User 預期合理（沒超界就沒得露），但點了沒反應可能 confused。Status 會顯示「露出 X 邊角（0 px；再按一次回中心）」勉強提示。Future enhancement: rot=0 時 button disable 或 hide
  2. **斜角度（如 30°）overflow 較小** — 30° 時 overflow ≈ 0.116·ts ≈ 70px，pan 也只 70px，可能顯得「不夠」 user 預期。實際上是對的（70px 就是真實超界量），但 UX 預期跟數學現實有 gap
  3. **學徒磚 900px + 大旋轉** — 900·0.207 ≈ 186px overflow，加上 viewport 尺寸限制，pan 後 canvas 自身 CSS max-width:100% 仍會把 900px 縮到 viewport 寬。這是 viewport 尺寸 + tile 尺寸雙重夾擊
  4. **頻繁切 pan + 旋轉組合** — overflow 是動態算的、ctx transform 每次 redraw 重組，無 cache 失效問題
  5. **2 dimensions 同活** — pan 跟 rotation 互相獨立，但 panState 在沒旋轉時沒視覺意義 → status bar 顯示「露出 X 邊角（0 px）」 多此一舉。可考慮 rot=0 時 togglePan 強制 reset center

## 6. 對 6z-3+ 的影響

**好消息**：6z-3 (tangle 庫 + ICSO) **完全不受影響**。Tangle render 在 outline 之後 draw，會被同一個 `withTileRotation` 包住 → 自動 inherit pan。Pan 機制是 viewport 層級、tangle 是 content 層級、兩者正交。

**6z-5 Pseudo-3D**：透視變形也會在 `withTileRotation` 內 apply → 透視 + 旋轉 + pan 三層 transform 自然 compose。

---

## 7. 經驗萃取（candidate）

> **Viewport 控制 vs 內容變換 是不同層**
>
> Pan / zoom / scroll 是 viewport 操作（只影響顯示、不改 content data）。
> Rotation / scale / pseudo-3D / fill 是內容變換（影響 content 的視覺 representation）。
> Canvas ctx transform 統一處理兩種，但 state 應分開存。
>
> 本 phase: `_rotationDegrees` (內容變換) + `_panState` (viewport) — 兩個獨立 dimension，互不重疊。

候選 memory；6z-5 加 pseudo_3d state 時若再次出現「N 個 dimension 各管各」 pattern，升格。
