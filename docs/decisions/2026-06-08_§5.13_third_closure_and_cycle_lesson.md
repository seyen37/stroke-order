## 決策 3：跨 10 天 cycle 是否該調整？

**觸發**：5/29 → 6/8 拉長到 10 天、catch 量 24（vs 5-7 天 cycle 7-17）、首次量爆炸。是否調整 audit cycle？

**選項**：

| 編號 | 方案 | 優點 | 缺點 |
|---|---|---|---|
| A | 維持 5-7 天 cycle、未來避免拉長到 10+ 天 | catch 量 manageable、處理時間 stable | 偶爾延後不可避免（如旅行 / 中斷）|
| B | 改 3-5 天 cycle、降低單次 catch 量 | 更頻繁 audit、量更小 | audit overhead 增加、user friction ↑ |
| C | 改 10-14 天 cycle、接受量爆炸 | 較少 audit | 處理時間 1.5-2x、容易 miss context |

**選擇**：☑ **A 維持 5-7 天 cycle**

**理由**：
> 5-7 天 cycle catch 7-17 commits（速率 1.4-3.4/day）、處理時間 stable 1-1.5h。10+ 天 cycle 累積量翻倍但速率 manageable、處理時間 1.5-2x 仍可接受、但不該作為 default cycle。
>
> 3-5 天 cycle 太頻繁、user friction（每次 morning audit + 6-command PowerShell + journal/decision 補寫）累積成本超過 catch 量降低收益。
>
> **明確 lesson**：5-7 天是 sustainable optimum、10+ 天作為例外處理（保留 1.5-2x buffer）、不是 new normal。

**後續驗證 / 結果**：
- ✅ §6.8 reinforcement 4 記錄 cycle 警示
- ⏳ 下次 audit day 預期 5-7 天 cycle、~10-20 commits

## 學到的規則 / pattern（適用未來）

### 規則 1：Sustained discipline 三段式回報週期 ~11-12 天平均

- 第 1 (10 天) §3.10 → §8.40
- 第 2 (11 天) SOP-0 → §3.19
- 第 3 (14 天) 候選 #1 → §5.12+§5.13

**回報三段式**：採用 → supporting case 累積 → formal close。**11-12 天平均回報週期可預測**。Long timeframe 紀律 > 短期 velocity。

### 規則 2：跨 10 天 cycle 量爆炸 lesson

5-7 天 cycle catch 7-17（速率 manageable）、10+ 天 catch 24+（累積量翻倍）。**5-7 天 cycle 是 sustainable optimum**、10+ 天作為例外（保留 1.5-2x buffer）。

### 規則 3：Governance 紀律有場景依賴性、評估「場景對應」

§5.13 升等對應 production-deploy 場景、本 repo audit-driven 不適用。**不是「升等就要套」**、要評估「場景對應」+「強套會否破壞既有 trace」。對應「workflow 設計避坑 > 規則記憶」精神延伸。

### 規則 4：Memory 更新 vs 新加判斷標準（4 條）

- **同 root cause family** → 更新（如 §3.20 R65 更新 PS encoding memory）
- **不同 root cause family** → 新加（如 §3.19 divergence vs §3.20 encoding）
- **跨 day 累積補強 / dogfood** → 更新
- **獨立新概念** → 新加（如 worst case sandbox 失能）

**Memory growth control**：跨 6 audit day +9 條新加 + 2 更新（1.5 條/day）— 標準形成後**更新比例上升**、新加放緩。

### 規則 5：Audit day 模式分布演化 1:3:2

5/29 預測「1 建立 : 3 新事件 : 1 閉環」、6/8 實測「1 : 3 : **2**」。**閉環 trace 比例上升**、隨 supporting case 累積、閉環頻率上升。

**未來預測**：第 4 個閉環候選（5/31 `2d9a84e` sandbox 不碰 mounted repo .git）若升等 → 模式分布可能演化為 1:3:3。Audit day 主軸**從新事件 driver 偏移為閉環 trace**。
