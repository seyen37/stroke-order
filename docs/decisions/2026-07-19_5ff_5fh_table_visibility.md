# 5ff～5fh 表格隱形字三部曲：QODA 重放（可見度契約、三態降級、旗標三現）

- **日期**：2026-07-19（第六階段）
- **版本**：0.14.247 → 0.14.250（af159cc → 03b84f7 → a9ff184）
- **對應原則**：§58–§60（並訂正 §57 同輪的「暫時性」誤判）
- **狀態**：5ff/5fg 使用者實機截圖實證；合併驗收 trigger 排程中

## 背景與誤判訂正

5fe 部署後「週期表×篆書大量空白格」再現。上一輪曾用 exact-URL
重放證明「伺服器/快取內容完好」而判暫時性——**那個結論本身沒錯
（伺服器真的完好），錯在推論**：內容完好 ≠ 畫面可見。空白的
真相在渲染層：字全在、整層 opacity 0.03。教訓＝「驗收要驗到
看得見」，計數（data-missing/synth 全對）不能替代畫素。

## 診斷方法：實機活體 DOM

沙箱 E2E 十輪未重現（代理字型讓多數字走可見的楷書軌跡路徑，
掩蓋了骨架路徑的隱形）。改用 claude-in-chrome 進使用者的 Chrome
重現全流程＋查活體 DOM，三分鐘定位：`#sutra-trace-skeleton`
computed opacity 0.03、116 個字形 group 全在。**使用者環境的
真相勝過沙箱推測**——環境差異（字型組合）會讓 bug 只在一邊現形。

## 決策一：可見度契約歸位（5ff）

篆/隸預覽的既有契約（5bz/5ca）：骨架層刻意 0.03 近隱形（骨架化
瑕疵不擾民），可見度由 sutra-glyph-reference 參考層扛。表格
wrapper 只轉發 emit_cellmap、沒轉發 show_original_glyph——
**§26「單一未轉發旗標」二現，同一個 wrapper 漏兩面旗**。修法
比照 body：route 建 outline loader（memoize＋glyph_chars 同
過濾）＋能力偵測轉發（`inspect.signature` 有此參數才給）。
連鎖痊癒：逐字手寫視窗範字（5eq 抓預覽參考層）同源修復。

## 決策二：traced_run 三態降級階梯（5fg）

五個自繪表格（乘法/節氣/部首/倉頡/注音）各自複製的 `_traced`
把骨架 fallback 包進 `stroke="none"` 群組——production 稽核
538/483/1019/241/72 條 polyline 全隱形。選項：A 各檔就地補
stroke／★B 抽共用 `traced_run` 統一三態。定案 B：

1. 外框字（楷書）→ 填色路徑照舊。
2. 骨架字＋outline loader → 參考層 0.55＋骨架 0.03（與內文頁
   同語意）。
3. 骨架字無參考 → 骨架**可見** 0.55——這些頁沒有雙層結構可靠，
   空白比瑕疵更糟（5dv「使用者就是要看到」同理；誠實降級）。

紅利：route 零改動（5ff 能力偵測自動涵蓋五表）；五份複製貼上
歸一（複製貼上的兄弟錯得一模一樣——修 bug 先 grep 兄弟）。

## 決策三：覆蓋稽核測試取代逐格找（5fh）

釓鋱二字退楷書＝5fa 建表漏收（與 Ext-B 七字同性質、第三批被
實機找出）。除了補條目（釓⿰金乚——勿用 乙，釔 才是 金+乙，
兩元素必須可區分；鋱⿰金弋），關鍵決策是**把「漏字」變成測試
紅燈**：118 元素完整覆蓋稽核——`resolve_decomp` 為 None 者只准
出現在白名單（原典古字 硫鐵銀金鉛）。資料表的完整性交給機器
守，不再消耗使用者的實機逐格檢查。

## 稽核方法學（線上驗收用）

SVG「有效可見度」稽核：走訪祖先累乘 opacity、繼承 stroke/fill，
判每條 polyline/path 是否真的畫得出來（>0.2 且 stroke/fill 非
none）。這是「驗到看得見」在無頭環境的替代品——比截圖便宜、
比計數誠實。
