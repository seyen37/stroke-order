# ADR — R3 手寫字型（user_dict 手寫軌跡 → TTF）

- 日期：2026-08-20
- 版本：0.14.292 → **0.14.293**
- 狀態：已實作
- 相關：FANGCUN 評估 `2026-08-11_fangcun_evaluation.md`（R3 原案）、R1a
  （長肉引擎）、§95.1（兩層驗證）、§28（純重構先立 seam）、§87（誠實）

## 脈絡

架上 R2／R3／B 三項，sign-off 順序 **R3 → B → R2**（R3 引擎/相依/資料全
就緒且獨家價值最高；B 已被 R1b 量測降級為小輪；R2 動工前有未解量測，第
一步是 spike）。R3 原案：「你的手寫變成字型」——FANGCUN 證明瀏覽器能出
OTF，但它沒有使用者手寫資料；本專案 user_dict 已存 EM2048 手寫折線。

## 決策（QODA）

### D1：字集只含寫過的字 ★（使用者 sign-off）

| 方案 | trade-off |
|---|---|
| ★ 只含寫過的字 | 每個字形都是本人手寫——誠實、情感價值最高；沒寫過的字 .notdef（字型正常行為）；寫幾個字就能出字型，零門檻 |
| 手寫優先＋骨架字補常用字 | 更實用，但混機器字形稀釋「你的手寫字型」的誠實性，且補字風格（圓體骨架）與手寫不一致 |

### D2：長肉引擎抽 seam，不是複製（實作決策）

R1a 的 `glyph_polylines` 綁死 g0v。抽出
`flesh_character(c, *, weight, cap, width_ratio) -> list[Polygon]`，
`glyph_polylines` 改薄包裝——**零行為變**（skeleton 三個測試檔原樣全綠）。

回 **shapely Polygon** 而非攤平折線：TrueType 是 nonzero 填色，外環洞環
必須反向——環向資訊只有 exterior/interiors 給得出來，攤平的 even-odd
折線給不了。這是既有輪廓契約（§27 even-odd 攤平）的邊界：字型是第一個
需要環向的消費者，seam 在來源端保留結構、不改既有契約。

### D3：環向明確定向，兩層驗證（實作決策）

- 環向以 signed area 明確定向（外環 CW、洞環 CCW，y-up 座標），不信任
  shapely 預設。
- **§95.1 兩層**：層一 fontTools 回讀（unitsPerEm=2048、cmap、全形等寬、
  輪廓數）；層二 **PIL/FreeType 真渲染**——「口」的字碗必須留白。環向錯
  時 nonzero 會把字碗填死，回讀看不出、只有真渲染看得出。spike 先產圖
  目視通過才寫測試。

### D4：著作權歸書寫者（承 FANGCUN 評估原則）

name table copyright 寫明「字形為書寫者之手寫創作，著作權歸書寫者本人」，
`owner` 參數可具名。本專案只是工具。

## 度量

EM 2048 恰好是 TrueType 慣用 unitsPerEm（零縮放）；手寫框下緣落在
descender（12% em → DESCENT 246／ASCENT 1802）；全形等寬 advance=2048。

## 介面

`GET /api/user-dict/font?weight=120&cap=round|square&owner=`——weight 經
R1a 密度補償；400＝還沒寫過字；503＝fontTools 缺席。UI：罕用字管理面板
「⤓ 手寫字型 (.ttf)」。

## 驗證

`tests/test_handfont.py` 14 項（兩層驗證＋著作權標注＋純手寫 cmap 鎖＋
weight 生效＋端點邊界＋UI parity）。全套 2215 passed / 56 skipped。

## 後果

- 寫過字的使用者一鍵得到自己的手寫字型，可安裝進 Word／簡報——寫字
  機器人工具鏈第一次「向上」輸出到字型生態。
- 誠實下限：沒寫過的字不顯示（.notdef）——這是特性不是缺陷；想要完整
  字集的路是「多寫字」，不是機器補。
- 後續可加：weight/cap UI 滑桿（API 參數已在）、字型內嵌預覽頁。
