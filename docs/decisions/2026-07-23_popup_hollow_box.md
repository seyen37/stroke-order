## 整體脈絡

使用者請求「立體字卡片」——打字後自動生出可折立的鏤空字 pop-up 賀卡（前立面是
鏤空文字、折起來字會立體突出）。核心難點不在網頁而在**機構**：文字怎麼折才會立
起來、卡片怎麼折才收得平、剪下來怎麼不散。我一開始照想像的機構寫，走了一段
逐筆 tab 的彎路，最後靠使用者的**實體折紙照片**才定案成最簡的鏤空箱型，才進
Phase 3 網頁模式。

---

## 決策 1：機構＝鏤空箱型（前立面＋頂/底摺線＋roof＋中線谷折對稱），不是逐筆 tab

**觸發**：「立體字卡片」的機構有多種可能實作。我先照 DAD 立體卡範本，把「文字頂
連接頂面」拆成**每個筆畫各一個小長方形 tab**，反覆多輪，使用者連回「差異太大、
根本不理解我的修改」。

**選項**：
- A（我原本走的）逐筆 tab：文字頂/底沿每個筆畫邊緣切出小長方形 tab 接 roof/底座。
- B（定案）鏤空箱型：前立面＝整片鏤空文字、文字頂＝**一條**摺線接 roof、文字底
  ＝**一條**摺線接底座、字中一條中線谷折、|字頂到中線|=|字底到中線| 對稱。

**選擇**：☑ B（使用者給實體折好的箱型照片後確認「這個鏤空箱型對了」）。

**理由**：正確機構其實**最簡**——文字頂是**一條**摺線，不是 N 個 tab。把「一條
摺線」誤讀成「每筆一個 tab」＝把最簡機構複雜化。A 之所以繞不出來，是因為我拿
紙上想像當機構、不斷疊特例；B 是實體折出來就對的那個。

**後續驗證**：✅ 單層（福/春）＋雙層（新年/快樂，兩箱疊成階梯、中線穿中間 tread
正中、上下兩排等高對稱）使用者實體試折皆站得好、收得平。

## 決策 2：鏤空字的材料是字身（實心），渲染實色；連筋保證整卡單一連通

**觸發**：前立面要「鏤空字」。一度把 tab/字身畫成白色留空（暗示是被剪掉的），
使用者回太不一樣。且鏤空後字內浮件（「口」「回」中心塊）剪下來會掉。

**根因/取捨**：鏤空字的語意是**字即結構**——**字身是材料（實心）、周圍才是透空
剪掉**；渲染要畫**實色**不可白色留空。而多輪廓字的內部封閉塊剪下後會與主體分離。

**選擇**：☑ 字身實色渲染；浮件用 `_connect` 補**最短縱向連筋橋**回主體，直到整卡
**單一連通（元件＝1）**。連通標記優先 `scipy.ndimage.label`，缺 scipy 退回純 numpy
run-based union-find `_label_runs`。

**理由**：實色＝符合「字即材料」語意；連筋＝剪下不散的物理保證，用測試鎖
`ncomp==1`。連通標記用選用相依（scipy）但**不硬性 require**——缺了要能降級
（承 §8），run-based union-find 比純 numpy BFS 快一個量級（雙層 24s→2.8s）。

**後續驗證**：✅ `test_single_tier_single_connected`／`test_two_tier_single_connected`
斷言 `ncomp==1`；`test_label_helpers_count` 雙驗 scipy 與 `_label_runs` 計數一致。

## 決策 3：可折合＝對稱不變式，用測試鎖

**觸發**：卡片要能平整折合（收起來）。

**根因/取捨**：要折得平，中線谷折必須穿卡片正中，且字頂到中線＝字底到中線
（|a-d|=|b-c|）；雙層再加上下兩排巢狀等高。這是幾何不變式，不是靠目視。

**選擇**：☑ 以測試鎖不變式——`test_spine_at_card_center_symmetric` 斷言 spine 在
`CH//2`、且 |字頂↔中線 − 字底↔中線| ≤ 2；`test_fold_layers_present` 鎖四類折線
（spine/mountain/valley/valley_seg）齊備。

**理由**：可折合是幾何對稱的直接後果，鎖不變式（對稱、折線分層存在）比鎖某個
座標值穩（承 §66 守門鎖不變式不鎖寫法）。

**後續驗證**：✅ 對稱斷言與折線分層測試皆綠；Playwright /popup 即時預覽單/雙層
連通、無 page error。

## 決策 4：字型是部署相依——缺字型測試 skip（不是 fail）、端點 503 帶指引

**觸發**：收工檢查.bat 首跑，6 個 popup 測試 FAILED，`CharacterNotFound：思源黑體
未安裝`。

**根因**：`NotoSansTC-Bold.otf` 不進版控、由 `scripts/render_fetch_fonts.sh` 於
Render 部署時抓；開發機沒放就缺。這是**部署期資源相依**，非功能壞。

**選項**：A 把字型 commit 進 repo（版控體積膨脹、授權/體積不宜）／B 需字型的測試
掛 skipif（沿用既有 `noto_hei` 那套）＋端點缺字型回 503 帶指引。

**選擇**：☑ B。

**理由**：字型該留在部署鏈（§9 字型即根因、§16 黑體字模已確立），不進版控。開發機
缺字型時，測試要**skip 不是 fail**（否則「開發機沒字型」誤判成功能壞）；不需字型的
測試（連通標記、頁面 200、空字/超長 422）獨立不掛守門，確保零字型也有回歸覆蓋。
端點回 **503 帶安裝指引**（執行 render_fetch_fonts.sh），把「缺字型」講清楚而非 500。

**後續驗證**：✅ 有字型 popup 8 過；無字型 2 過 6 skip、零 failure。全庫 1855
passed／68 skipped。

## 沒做的決策（明確擱置）

- **PDF 自建管線**：pop-up PDF 沿用既有 `/api/card/pdf`（SVG→PDF via cairosvg），
  不另造一條，避免重複匯出路徑。
- **popup.html 拆 ES 子模組**：刻意做成自包含內嵌 JS 單檔，不引子模組——避開 §67
  「子模組相對 import 缺 ?v= 半破快取」整類坑；此頁夠小、內嵌成本低於多一組快取鍵
  紀律。

## 學到的規則（→ PRINCIPLES §68）

**紙藝／實體機構先折一個實體原型定案，再寫幾何**：程式碼描述的是「摺起來會立起來
／收得平」的實體行為，紙上想像最容易把「一條摺線」複雜化成「每筆一個 tab」。誤讀
使用者修改時（尤其使用者連說「不理解」），停手、要一張定案圖（實體照片），回到最簡
機構（Occam），別基於自己的想像疊修正。鏤空字＝字身實色（字即材料）、浮件補連筋
保證單一連通（剪下不散）；可折合＝對稱不變式（中線穿正中＋|a-d|=|b-c|），用測試鎖。
姊妹律一（**部署期字型相依→缺則誠實降級**，承 §8/§9）：字型不進版控、由部署腳本抓；
本機缺字型時需字型的測試 skip（`needs_hei` skipif）、端點回 503 帶指引，別讓「開發機
沒資源」誤判功能壞。姊妹律二（**選用相依要能降級**，承 §8）：連通標記優先 scipy、缺
了退回純 numpy run-based union-find，同測試雙驗兩路徑一致——選用相依不可硬 require
擋住整個功能。
