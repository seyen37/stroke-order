# 決策紀錄 2026-08-20（W3）：QR code——紙本 → 線上字典

對應 PRINCIPLES §95（**深連結不是 API 整合**：只連不抓就沒有金鑰與相依；
新元件的正確性要對照參考實作驗，能的話再拿獨立解碼器端到端驗一次）。承
§8（誠實降級）、§68／§86（不要引入執行期外部相依）、§76（單一事實源）、
T3 的自包含鐵則、§93（下結論前覆查）。版本 0.14.289。

---

## 整體脈絡

字帖評估建議書盤出的三個缺口之三：**紙本連不回線上**。同好的字帖產生器在
每個字旁附教育百科的連結與 QR，學生把單子印出來、掃碼就能自學——那是那份
借鏡裡最好的點子，而本專案完全沒有。

---

## 決策 1：只做深連結，不碰教育百科的 API

**Question**：教育百科有 Open API（`/api/v2/Detail`），要不要用？

**答案是不要，而且理由是結構性的**：那個 API **要註冊 api_key**
（`https://pedia.cloud.edu.tw/Home/OpenAPI`）——執行期外部相依＋密鑰管理，
正是 §68／§86 花兩輪根治掉的東西。

**關鍵發現：我們根本不需要它。** 詞條頁本身是純網址：

```
https://pedia.cloud.edu.tw/Entry/Detail?title={URL-encoded 單字}
```

實測「春」回 **HTTP 200、246,998 bytes**。編碼進 QR **完全不必連網、不必
金鑰、離線可產**，而且我們只「連過去」，不抓也不轉存對方內容——沒有額外的
出處或授權義務。

**通則（→ §95）：想接一個外部服務時，先問「我需要的是它的資料，還是只是
一個能到它的入口？」** 若是後者，深連結就夠了，成本是零。

---

## 決策 2：QR 放 `/teach` 教學單，不放 grid 字帖

**Question**：字帖（grid）與教學單（/teach）都能放，先做哪個？

**選項**：★ A `/teach` 教學單／B grid 字帖頁尾生字索引／C 兩者都做。

**選擇**：☑ A（使用者 sign-off）。兩個理由：

1. **最貼近同好描述的用法**——他說的是「下載列印後，掃碼就可以連過去，
   方便學生自學」，那正是 `/teach` 的自包含教學單（單字一頁，有筆順動畫、
   部件、字義、造詞、插圖槽）。
2. **零回歸風險**。grid 是單張、px 座標、無分頁的 SVG，要塞 QR 得在底下加
   一條頁尾帶——那會**改變所有既有字帖的輸出尺寸**，必須做成 opt-in 才不
   算回歸。`/teach` 是純新增區塊，不動任何既有輸出。

`/api/qr` 刻意做成**獨立端點**而非塞進 `/api/dict`：它與字典無關，日後
grid 頁尾要用也是打這一個。

## 決策 3：連教育百科，不連簡編本（附取捨）

**這裡有個一致性問題值得記下來**：我們印在紙上的釋義來自**國語辭典簡編
本**（`data/moe_dict_bundle.jsonl.gz`），而 QR 連到教育百科，內容未必等於
紙上那段。

| 目標 | 網址 | 實測 | 取捨 |
|---|---|---|---|
| **教育百科**（採用） | `Entry/Detail?title=春` | 200 / 247 KB | 直達詞條、內容最豐；但是百科整合版 |
| 簡編本搜尋 | `dict.concised.moe.edu.tw/search.jsp?word=春` | 200 / 15 KB | 與紙上同源，但落在搜尋頁、要多點一下 |
| 簡編本永久連結 | `dictView.jsp?ID=32885` | 200 | **我們沒有 ID**——bundle 欄位只有 `c/zy/rad/sc/df/w` |

**選擇**：☑ 教育百科（使用者 sign-off）。學生掃碼要的是「直接看到東西」，
多一次點擊的成本比內容版本差異更實際。簡編本永久連結要重建 bundle 才能
支援，不在本輪範圍。

## 決策 4：加 `segno` 相依（BSD，零執行期相依）

**選項**：★ A 加 `segno`／B 前端 JS 產／C 自己寫 QR 編碼。

- **B 前端 JS**：不加 Python 相依，但下載的自包含教學單要能**離線**重現
  QR，就得內嵌整個 JS 函式庫——反而更肥，而且違背「下載檔零外連、零腳本
  相依」的方向。伺服器產生＋內嵌 SVG 的話，下載檔連 JS 都不需要。
- **C 自己寫**：約 300 行含 Reed–Solomon 糾錯。這不是本專案該自己維護的
  東西。

**選擇**：☑ A。查證（§93，因為我在建議書裡寫錯過一次）：

| 項目 | 查證結果 |
|---|---|
| 授權 | **BSD**（`License :: OSI Approved :: BSD License`）——建議書原寫 MIT，**錯**，已訂正 |
| 執行期相依 | **零**（`importlib-metadata` 只在 Python < 3.10 需要，本專案 `>= 3.10`） |
| 安裝體積 | 577 KB |

**缺席時降級為不印 QR**（`QrUnavailable` → `/api/qr` 回 503 → 前端只留可點
連結），字帖與教學單其餘內容照常產出（§8）。

**不自己用 segno 的 SVG writer**：它只吃 bytes buffer，而且我們要控制配色
與模組尺寸以配合教學單版面。它暴露 `q.matrix`，所以依矩陣自己組 `<rect>`
——與本專案「自己組 SVG 字串」的既有風格一致。**同一列連續的暗模組併成
一個 `<rect>`**：實測 573 個暗模組併成 282 個 rect，內嵌進自包含教學單時
標記量減半。

## 驗證：兩層，第二層是獨立解碼器

**第一層（進版控的測試）**：把我們產出的 SVG **反解回暗模組座標集合**，
與 `segno.make(text).matrix` 逐格比對。這是在驗**我們的 emitter**——座標
算錯、靜區位移、合併 rect 的寬度算錯，全都會紅。不引入新相依。

**第二層（一次性 spike，不進版控）**：用 **OpenCV 的 `QRCodeDetector`**
把產出的 SVG 光柵化後真的解一次。四個字（春國歡永）全部解回**完全正確的
網址**。這回答的是第一層回答不了的問題：「掃描器真的讀得到嗎？」

> 這兩層的分工值得記：對照參考實作證明**我們沒寫錯**，獨立解碼器證明
> **成品真的能用**。前者可以留在測試裡天天跑，後者做一次就夠——但不做的話
> 就只是「和另一套實作算出一樣的東西」，不等於「掃得到」。

其餘：

- 三個定位圖案（7×7 角落）逐格驗——沒有它掃描器找不到 QR。
- 網址樣板單一事實源：`/api/dict/{char}` 的 `entry_url` ≡ `pedia_url(char)`，
  且 **grep 鎖住 teach.html 不得出現 `pedia.cloud` 字面值**。
- 自包含：`buildDoc()` 內嵌 `cur.qrSvg`，且**下載檔不得出現 `/api/qr`**
  （grep 鎖）。
- `tests/test_qr.py` **27 項**全過；全套 pytest **2134 passed / 56 skipped**。

## 過程中被既有守門攔下的兩件事

1. **`/api/qr` 沒進路由快照**（`test_route_snapshot`）——補上。
2. **我自組 `Response` 並硬寫了 SVG 的 media type**，被
   `test_svg_media_type_written_once` 攔下（全站只准寫在 `responses.py`）。
   改用 `svg_response(svg, mode=None)`——`mode=None` 是明示「QR 不是可分享
   的作品、不嵌 5fv 出口信封」，同時滿足另一道要求呼叫點明示 `mode=` 的鎖。
   **第一次修完還是紅的**：那道守門連**註解裡**的字面值都算，而我在註解裡
   引用了它。重寫措辭而不是放寬守門。
