## 學到的規則 / pattern（適用未來）

### 規則 1：Source case → thesis 升等閉環

5/14 day 1 採用 §3.10 default-deny 是「點」、6+ 天後升為 §8.40 二維 thesis 是「線」。**source case provider 的價值在 long timeframe 才浮現** — 即時看是「不超前升等」的保守、6 天後看是「sustained discipline」的回報。

**啟發**：governance 紀律累積有滯後效應。長期紀律 > 短期 velocity。

### 規則 2：Contingency memory 標準形成（第 2 條同類）

5/19 寫 `feedback_sandbox_unavailable_fallback` = 第 1 條 contingency memory；5/24 寫 `feedback_ps5_chinese_encoding_three_layers` = 第 2 條同類。**共同特徵**：0 命中 + 高 impact + 短反應時間 + marginal cost ~30 min + option value 高。**標準形成** — 未來遇到同款情境直接套模板、不用每次重思考。

### 規則 3：Cross-ref 對「正式紀律」做、不對「候選」做

§8.40 是正式紀律 → 立即 cross-ref（決策 1 選 A）。13bbcc7 5 條候選紀律 → 不 cross-ref（5/19 day 3 決策 2 不超前升等）。**Cross-ref 與升等是不同層級操作** — cross-ref 是「對齊 SoT」、升等是「做 governance 決定」。本 repo 做前者、不做後者。

### 規則 4：Audit ROI 的滯後性

4 個 audit day 累計 803+ lines 治理、0 feature code、6 commit。ROI 不是即時可見的、是 phase 6z+ 開動後才兌現（0 個 debug 走錯方向 / 0 個 sandbox 失能臨時想 SOP / 0 個 governance drift）。**Patience > 急著進 feature**。

### 規則 5：Fetch-first SOP catch 量 exponentially growing 警示

5/14 day 2 catch 1 → 5/19 catch 7 → 5/24 catch **17**。**跨 device session 並行頻率持續增加** — SOP-0 從「規則」變「生活方式」。預期下次 audit day catch ≥ 17，需 5-7 天 cycle、不要拉長到 10+ 天（catch 量會爆炸性增長、處理時間 ↑）。
