## D1. 參考庫的用法：套現成模板 vs 自寫專屬 DESIGN.md

**Question**：使用者分享 VoltAgent/awesome-design-md，要「做為介面設計
參考資料」。

**Options**：A＝自寫專屬 DESIGN.md（把 5fp~5fu 稽核弧已上線的設計語言
成文，參考庫只借格式慣例）；B＝挑一份現成風格模板改編。

**Decision**（使用者 sign-off A）：本站的設計語言**已經存在且有測試鎖著**
（藍/紅語意、按鈕四階、空狀態句式…），缺的是文件而非風格。套模板反而會
引進與現況衝突的規範。參考庫的價值在**九節格式慣例**與「機器可讀 token
表」的做法。配套：`tests/test_design_md.py` 同步鎖讓文件與 CSS 綁死——
文件是執法依據，不是會腐化的快照。→ §81。

## D2. 改進的節奏：一次大掃 vs 盤點→複選→分輪

兩次都走「量測盤點→提案數輪→使用者複選→依序施工」：第一次提 4 輪選 2
（5gb 設計一致性＋5gc 收工腳本），第二次提 3 輪全選（5gd/5ge/5gf）。
每輪獨立 commit、獨立版本、獨立 E2E，寫回一次、bat 一次入帳（消費制與

數字**框定（「四種藍」「六處 import」「31 處 chip-bg」），不憑印象開工。

## D3. info 框歸一的 accent 色：獨立新色 vs var(--primary)

**Decision**：`--info-accent: var(--primary)`——資訊提示框左緣線歸主要
動作藍，不再發明第五種藍。取捨：同步鎖的 `_ROW_RE` 只驗 `token: #hex`
字面，`var()` 別名進不了表——故 bg/fg 進表、accent 記在「衍生」段。
教訓（測試工法）：回流鎖用「字面出現即紅」時，**豁免規則要同批設計**
（token 定義行、含「歸一」的註解行豁免；3 碼 hex 斷言「後不接 hex 字元」
防 `#494` 誤中 `#494a5b`）。我們自己的測試 docstring 與 CSS 註解就誤中過
兩次。

## D4. ES 模組 ?v= 補法：逐檔漸進 vs 同模組全站一批

**Question**：5fw 時曾刻意「沿用無 ?v= 匯入避免雙實例」，現在要收口。

**Decision**：**同一模組的所有 import 點一批改**——雙實例的成因是「同
模組出現兩種 URL 字串」，不是「有沒有 ?v=」。gallery.js×3＋uploader.js
＋auth.js 動態匯入 ×2 六處同批補 `?v=__V__`，注入後全站同版號＝同 URL＝
單一實例，且版更即擊穿舊快取。E2E 驗「hash.mjs 只以一種 URL 被請求」。

## D6. --accent 同名反義：改名遷移 vs 語意歸位

**Question**：`--accent` 三頁三義（主站紅/card 藍/popup 綠）。card 的
「藍 accent」有 4 個 CSS 用點＋編輯器 chrome 5 處；popup 的「綠 accent」
1 用點。

**Decision**：**語意歸位**——`--accent` 全站唯一語意（破壞性/錯誤紅
#c33），凡當主色用的一律改 `--primary`。token 的**值**可以依作用域分
（--gl-*/--hw-* 前綴），**語意**不可以：同名反義比散寫 hex 更毒，因為它
會誤導「照文件動手」的人。機械替換的例外要逐點判別：sutra-editor 六處
`status.style.color=var(--accent)` 全是錯誤訊息→紅是對的，保留；popup
摺線圖例綠 #149046 是輸出品語意色→不動。card 編輯器 chrome 藍改 #2c5cb8
時，test_card_editor 的三處 `fill="#1976d2"` 斷言同批改。→ §82。

## D7. 版面「統一」：硬套同一寬/斷點 vs 例外成文＋分岔修平

**Question**：頁寬 960/1400/full-bleed、斷點 640/767/480 並存，統一嗎？

**Decision**：**先分「合理差異」與「不合理分岔」**。分享庫/筆順練習 1400
是瀏覽工作區的合理選擇，硬壓 960 會讓卡格變少（負優化）；筆順練習 767
斷點是雙欄工作區的合理值——這些**成文為例外**（容器三檔、斷點準則進
DESIGN.md）。真該修的是 handwriting.css **同檔並存 760/767**（7px 窗內
行為分岔，無任何語意）→修平＋單一斷點鎖；「←/↩ 回主頁」混用→統一＋鎖。
硬套一致性是反模式；成文的例外就是一致性。→ §83。

## D8. 識別色收斂：消滅雜色 vs 具名 token 化（值不變）

**Question**：主頁 inline 尚餘 ~180 hex，其中大宗是各模式欄位框家族色。

**Decision**：這批是**刻意的識別設計**（製造群米黃、曼陀羅裝飾暖橘…），
債不在「有色」而在「散寫」——收斂 16 個具名 token、**值一律不變**；僅
同族內雜色（#b09a66/#8cc/#d97 三處）歸一到族代表色並在註解點名。驗收
哲學：**重構的驗收是證明沒變**——E2E 逐一比對代表元素 computed style
＝原色值，證明 token 解析成功而非 fallback。回流鎖擴 21 色後，「新色先
進 DESIGN.md 色表再使用」的護欄第一次有了牙齒。→ §84。
