## 背景

使用者兩批截圖規格（5fc 七點版面、5fe 合成間距/週期表篆字/按鈕

## 決策一：hidden 失效的修法（5fc）

素材面板全展開、部首路線常駐、抽屜常開——三症看似三個 JS bug，
實為一源：CSS `.xxx { display:flex }` 優先權蓋掉 UA 的 `[hidden]`
規則。修法選項：A 每處改 `.xxx:not([hidden])` ／★B 一行全域
`[hidden] { display: none !important; }`。定案 B——歸位一次、
未來新元件自動受保護；JS 切換邏輯本來就對，不動。

## 決策二：深連結分流語意（5fd）

「從哪來就回哪去」：`preset` 參數存在且下拉有此選項 → 素材切
「經典」＋載入＋ `chars.indexOf(_deepChar)` **定位到該字**；否則
（字帖/筆記等）切「字串」帶字。字體一律「先套再單次 renderBg」
——避免二次渲染閃爍。判準用「選項存在」而非「參數存在」：壞
preset 誠實退字串路，不出半載入狀態。

## 決策三：合成幾何 bbox 正規化（5fe）

實機：罣 上下大縫、釕 左右大縫、整字瘦長。根因不是槽位比例沒調
好，是**縮放整個 EM 把部件自身留白也帶進槽**——縫＝設計縫＋
兩件 side bearings × 縮放，怎麼調比例都治標。定案：改「部件
outline bbox → 槽位矩形」仿射，縫隙成為設計值（88/2048），整字
撐滿正方；`_STRETCH_CAP = 1.75` 上限保護窄件（了/乙 硬拉滿槽會
爆形——寧留小縫不毀形，與 §53 誠實取捨同路數）。

## 決策四：Ext-B 七字補全＋帳目修正（5fe）

𨭎 顯示楷書的根因＝ **ELEMENT_DECOMP 缺 7 條**（𨧀𨭎𨨏𨭆䥑
鿬鿫——Ext-B／新收錄字）而非渲染 bug。補：金杜/金喜/金波/金黑/
金麥/石田/气奧。同時修正 5fa 驗收帳目：「118＝62 合成＋56 原典」
實為 62＋49＋**7 楷書 fallback**——當時計數只分「缺/不缺」兩態，
fallback 被算進原典。**覆蓋率驗收要三態分列（合成/原典/退化）**。

## 決策五：空白格「不修」（5fe）

週期表預覽大量空白＋狀態列卻「✓完成·62 合成」——用前端一模一樣
的批次 URL（含參數序、verse 值）重放 production：**快取內容 6/6
完好**；本機完整 E2E 前端合併全綠。判定＝按預覽撞上部署重啟窗口
的暫時性故障，**不寫推測性防禦碼**（未重現的 bug 寫補丁＝把猜測
固化進 codebase）。給使用者硬重整＋重按預覽的動作；若再現再抓
DOM 現場。

## 決策六：grid 版面與版本可觀測性（5fe）

右欄頂對齊米字框上緣：`.hw-canvas-row` 改 grid、右欄 (2,2)；
`.hw-canvas-col` 用 `display: contents` 保 DOM 不動（測試鎖）。
兩個 grid 陷阱實地踩過：動態插入的來源提示被 auto-placement 吃進
(1,2)；改跨欄後其 max-content 又分配進右欄撐爆欄寬——終解＝
**動態內容插 grid 容器之外**。版本可觀測性：頁首手刻 v0.13.0 卡
十幾版、CSS 無 ?v=（TTL 3600s 隱形舊版窗口）都在這輪誤導過部署

「一切版本顯示走注入，不手刻」。
