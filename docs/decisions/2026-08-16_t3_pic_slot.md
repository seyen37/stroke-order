# 決策紀錄 2026-08-16（T3）：插圖槽——先量覆蓋率再決定要不要付永久成本

對應 PRINCIPLES §89（外部資產先量「對本用途的覆蓋率」再決定是否打包；量測
數據留在 ADR 供翻案；產品定位鎖成機器可驗）。承 §75（估工前盤 choke point）、
§87（不做生成）、§88（ND 授權）。commit：`0fd11be`（0.14.285）。

---

## 整體脈絡

T3 原範圍是「插圖槽（老師自備圖或留白）」。動工前發現教育部同授權下也有官方
插圖檔——若可用，就從「老師自備」升級成「常用字自動配圖」。故先量測再決定。

---

## 決策 1：不打包官方插圖——覆蓋率不足以支撐永久體積成本

**觸發**：官方插圖檔 13.5 MB、同 CC BY-ND 3.0 TW 授權，技術上可打包。

**量測（決策依據，供日後翻案）**：

| 項目 | 數值 |
|---|---|
| 圖檔數 | 856（619 jpg＋237 gif），13.5 MB |
| 詞對應 | 1,149 筆／1,111 個相異詞（含「綜合主題圖」一圖多詞） |
| 單字條目直接有圖 | 435 |
| **教學頁覆蓋率**（直接有圖，或其造詞有圖） | |
| ├ 全 6,028 單字 | 722（**12.0%**） |
| ├ 國小常用 5,021 字 | 689（**13.7%**） |
| ├ 常用 808 字 | 174（**21.5%**） |
| └ 最高頻 500 字 | 112（**22.4%**） |
| 示範字「園」 | **無圖** |
| repo 體積影響 | `.git` 17 MB → 約 31 MB（**翻倍**） |

**選項**：A 打包全部（最高頻字 ~22% 自動配圖，git 翻倍）／B 部署時抓（repo
不肥，但多一條部署相依——正是 §68/§86 花兩輪根治的痛點）／C 不納入，只做
老師自備上傳槽。

**選擇**：☑ C。

**理由**：**約五個常教的字才命中一個**，而老師無論如何都要為另外四個準備圖
——B 案的邊際價值只是「少數字少準備一次」，卻要付永久體積或部署相依。對照
T2：辭典 2 MB 換 100% 字有字義，命中率天差地別；**同樣是官方開放資料，值不
值得打包完全取決於對本用途的覆蓋率，不能因為「官方有、授權可、技術可行」就打包**。

**訂正紀錄**：量測過程中我一度宣稱「索引引用的檔案有缺」，覆查後為誤判——
856 個引用全部存在，是我先前只數 `.jpg`、漏掉 237 個 `.gif`。數據在下結論前
必須覆查（§88 精神：斷言要能被驗證）。

## 決策 2：插圖一律內嵌 data URL，不外連

**觸發**：下載的教學單檔要能離線在教室打開。

**選擇**：☑ 選檔或剪貼簿貼上→長邊 >900px 以 canvas 縮放轉 JPEG→內嵌 data URL；
下載檔的 `<img src>` 必為 `data:`。

**理由**：自包含是這個下載檔的存在理由（老師隨身碟帶去教室、無網路）。外連
圖片＝在教室破圖。縮放上限則是避免單檔動輒數 MB。

**後續驗證**：✅ Playwright 實測 1400px 圖縮到 15 KB；下載檔正則掃描確認**零
非 data 的 img src**、仍無 `<script src=`。

## 決策 3：把「不做生成」鎖成機器可驗

**觸發**：T3 最容易的擴張就是「乾脆接個影像生成」——那正是評估時明確否決的
方向（§87），但否決只寫在文件裡擋不住未來的自己。

**選擇**：☑ 守門測試斷言頁面**不得出現任何影像生成端點字樣**。

**理由**：與 §88 的 ND 守門同一手法——**產品定位與授權義務都不能只靠文件**，
寫成測試才有約束力。

## 沒做的決策（明確擱置）

- **官方插圖走部署時抓或 CDN**：若日後覆蓋率提高、或改成「按需單張抓」不落地，
  可翻案；本 ADR 的量測表就是翻案依據。
- **多張插圖／圖說欄位**：目前一張足夠，未過度設計。

## 學到的規則（→ PRINCIPLES §89）

外部資產（資料／圖庫／字型）在打包前先量**對本用途的覆蓋率**，不是看它總量
多大或授權多友善；覆蓋率決定值不值得付永久成本（repo 體積、部署相依）。量測
數據要留在 ADR 供翻案。下結論前覆查自己的數字。產品定位（如「不做生成」）
與授權義務一樣，寫成守門測試才有約束力。
