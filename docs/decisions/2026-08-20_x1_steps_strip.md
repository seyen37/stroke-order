## 脈絡

第四份借鏡（筆順合併自動插圖作業單產生器）的田野證據：老師拿生字列表，
從筆順字典網站抓「第 N 格畫到第 N 筆」的靜態分解圖貼 Word，動機是**省
筆順字型的錢**。本專案逐筆資料（g0v 教育部標準楷書）與累積渲染邏輯
（gif.py）都在，唯獨沒有列印用靜態輸出——「資料在、沒排」。

## 決策（QODA，使用者 sign-off）

### D1：新端點 `/api/steps` 批次出圖 ★

| 方案 | trade-off |
|---|---|
| ★ `/api/steps?chars=…` 每字一條、自動換列，svg/pdf/png 走 W1 出口 | 最貼近他工具的產出物（一張紙全是分解圖）；不動 grid 既有版面 |
| grid 字帖 opt-in 分解圖列 | 與練習格同紙，但版面變數多（筆畫數差異大）、成本高 |
| 只在 /teach 加單字下載鈕 | 最薄，但不服務批次工作流（田野證據的核心） |

UI 入口放字帖模式（共用「字串」生字欄與「格線」選項），兩顆鈕：預覽
SVG／下載 A4 PDF。

### D2：已寫淡灰＋當前濃黑＋小序號 ★

**黃金規則：黑白影印後仍可辨**（讀寫障礙教室幾乎必然黑白影印）。

- 已寫 `#b3b3b3`、當前 `#111111`——灰階單調遞增。**刻意不沿用 gif.py 的
  紅色 highlight**：`#c33` 灰階後比 `#333` 淡，影印下當前筆反而變淺。
  測試鎖「當前亮度 < 已寫 −60」的現象，不鎖色值（§66）。
- 序號走 noto_hei 字形路徑（§5bv），字型缺席整個省略不補符號（§87）；
  加**白底護墊**（後段格子墨滿，序號無論放哪都可能壓字），墊高用序號
  字形實測墨跡帶算（§96.2）。

### D3（實作中）：envelope `mode=None`

envelope 的 mode 會流進分享庫收件側的 kind 白名單（12 模式數量鎖）。
分解圖暫不進分享庫——照 `/api/qr` 前例刻意不嵌信封並註明理由；登錄第
13 個 export kind 留給真的有人要分享的那一輪。

## 實作要點

- `exporters/steps.py`：重用 grid 的 `_outline_or_track`／`_guide_paths`
  （不另寫渲染）；每字 `<g class="step-strip" data-char data-steps>`、
  每格 `data-step="k"`；頁寬恆為 `cols` 格（§96.1：與單字筆畫數解耦）。
- `char_pipeline.build_digit_glyphs()`：0–9 的 noto_hei 字形表，缺席回空。
- pdf/png 與 grid 同路：`fit_svg_to_paper` → 光柵化，配額與誠實標頭
  （`X-Pdf-Dpi-Used`）全沿用。

## 過程中的錯（§96 再次生效）

序號第一版沿用 W2 的全形步進 helper——noto_hei 阿拉伯數字是**比例寬**
（約半形），全形步進排成「1␣0」，低倍率下像只印了個位數。斷言全綠、
**放大產圖才看見**。改窄步進（0.55 字級）並鎖「兩位數序號兩個字形群
都在」。這是 §96「有版面的功能收工前產圖用眼睛看」第四次抓到問題。

## 驗證

`tests/test_steps_strip.py` 20 項：格數＝筆畫數／逐格累積／灰階單調＋
紅色缺席／換列與畫布界內／`<text>` 缺席／字型缺席省略不補符號／兩位數
完整／端點 svg·pdf·png·422／guide 生效／UI parity。全套 2201 passed /
56 skipped。產圖目視：春·永·歡（22 畫 3 列）含灰階模擬。

## 後果

- 老師輸入生字列表 → 一鍵 A4 分解圖，不必再抓外站；「原生且授權乾淨」
  對「抓取且授權模糊」的直接替代。
- 產出物可直接另存插進 Word（X2 之前的過渡用法）。
- 分解圖不進分享庫、超長字表單頁縮放（不分頁）是本輪的誠實下限，均已
  註明升級路徑。
