## 1. Thesis 再再平衡（第三波）

### 1.1 Modal 在 creative tool 是反 pattern

| Modal 適用場景 | Inline 適用場景 |
|---|---|
| 不可逆 transactions（轉帳 / 刪除 / 上傳）| 可逆 settings（mode / size / color）|
| 需要 confirm step（hard delete）| 持續微調（slider / radio / dropdown）|
| 多欄位一次提交 batch（form wizard）| 單一欄位即時影響（filter / preview）|
| Destructive actions | Creative actions |

Phase 6z 是 creative tool — 紙磚 + tangle + 顏色 + 旋轉都該是 **直接操作 + 立即反饋**。Modal popup 對 settings = friction + 認知負擔（需要 close → 再 reopen 才能再調）。

### 1.2 三次 course-correction 的 root cause

| Iteration | 觸發 | 改動 |
|---|---|---|
| 6z-1F (`def8f38`) | 設計時套 D-C 強紀律弱預設 | force-modal 第一次必填 + ESC 不可關 + 無預設值 |
| 6z-1.1 (`ca83132`) | User 反饋「預設就是心+空心+標準磚，先讓使用者開磚」 | DEFAULT_CONFIG fallback + modal 改非阻擋 |
| **6z-1.2 (本 commit)** | User 反饋「inline 點選立即更換預覽」 | 完全移除 modal + inline radio + change 即 render |

三次同方向的修補（每次都是 → 更少 friction → 更直接操作）= **root cause 是「把 modal 當 settings 入口」這個錯誤前提**。每次 patch 一點是治標。第三次根除：**直接刪 modal**。

對位 personal-playbook §8.32「失敗 2 次換方法 反偷懶協議」 — 兩次同類修補後，第三次該 strip and rebuild，不是再修補。

### 1.3 Memory 已存

`feedback_domain_specific_defaults.md`（5/7 saved）已涵蓋 ops vs UX 的預設策略差異。本次擴充：**creative tool config = inline + auto-apply**，modal 只該用於 destructive / irreversible transactions。不另開新 memory，inline 補充進既有條目即可（看後續是否升格 memory）。

### 2.4 誠實標註：mode + tile_size 視覺差異延遲

| 控件 change | 6z-1.2 立即效果 | 視覺差異到位的 sub-phase |

| 字 input | ✅ outline 重 fetch + render | 已到位 |

## 4. P7-COMPLETION

- **任務**：取消 modal popup、改為 inline radio + change 即 persist + re-render
- **方案**：刪除整段 `<div id="zentangle-modal">` 95 行 + modal-related JS 105 行；新增 `wireInlineControls()` 90 行 (debounce + radio + select listeners)；updated `applyConfig` 同步 radio state
- **改動**：3 files (index.html / zentangle.js / pyproject.toml) + 1 new doc
- **影響分析**：
  - 既有 ACTIONS dispatch / 鍵盤滑鼠 listener / canvas render pipeline → 不受影響
  - DEFAULT_CONFIG / localStorage schema / readConfig 等 persistence → 不受影響
  - 33 tests 全 pass、HTML smoke 9/9 → no regression
- **三問自審**：
  - 方案正確：是。Modal 對 creative tool 是反 pattern；inline + auto-apply 對齊 acquisition-first thesis
  - 影響全面：是。grep `zm-` / `zentangle-modal` / `wireForceModal` → 確認所有引用都清除
  - 回歸風險：低。改動範圍局限於 zentangle 模式、其他 11 mode 完全不動
- **剩餘風險**：
  1. **mode + tile_size 點選沒有立即 canvas 視覺差異** — 文字 status 提示 user，但 acquisition target 可能仍期待立即視覺反饋。Trade-off：保留 modal 等到 6z-2/3 視覺到位 vs 現在就建立 inline pattern。後者更對；status 提示已誠實標註
  2. **6z-2 canvas resize 對 outline.mjs 影響** — `mapContourToTile(contours, bbox, tileSize, margin)` 已 parameterize tileSize，6z-2 改 canvas 寬高 + tileSize 即可，無架構改動
  3. **6z-3 mode 視覺實作** — 純禪繞 / 空心填充 / 背景鑲嵌 三 mode 的 fill 邏輯 spec 還未細化，到 6z-3 spike 時要回頭定 spec
  4. **3-strike 模式** — Phase 6z-1 三次連續修補 force-modal 區，揭示「設計階段過度 enforce 通則」的傾向。下次 phase 設計該 sanity-check：「**這個 enforcement 對 acquisition target 是 friction 還是 value**？」

## 5. 對 6z-2/3+ 的影響

### 6z-2 紙磚 rotation
- inline pattern 延伸：旋轉 slider / cycle button → change → canvas 立即 redraw
- tileSize radio 點選 → canvas resize logic 同時上線（合併 6z-2a 動工時順便處理）

### 6z-3 ICSO + tangle 庫
- mode radio 視覺差異 = fill phase 的判斷分支：
  - `pure` (純禪繞)：只填 outline 內部
  - `hollow` (空心填充)：留 outline 邊界空白、外圍填
  - `bg` (背景鑲嵌)：整磚填、字反白
- 6z-3 spec 階段細化每 mode 的 fill 邏輯

### 6z-7 input full wiring
- inline 控件不衝突 PS2/gamepad scheme — controllers 通過 ACTIONS dispatch 也可改 mode/tile，但 6z-1.2 不做（PS2 尚未 wire）
