# 決策紀錄 2026-07-22（5fm/5fn）：逐字手寫範字大小——墨跡實框正規化為跨呈現面共用契約

對應 PRINCIPLES §64（墨跡實框正規化＋巡全消費路徑）、§65（脆弱慣例升級成自動閘門／
fail-open 新鮮度守門）、§66（守門鎖不變式不鎖寫法）。承 5eq（§34 styled 範字挑對圖層）、
5fb（範字 1.4× 放大）。commit：`400d4d5`（5fm, 0.14.259）／`5a1bd43`（收工檢查守門）／
`2a9c0a3`（5fn, 0.14.260）。

## 整體脈絡

逐字手寫（點格→米字格照描）的範字在多個呈現面出現：稿紙/字帖/筆記/信紙的彈窗、
抄經彈窗、以及獨立 `/handwriting` 練習頁。5fb 為了「範字大一點好寫」在共用繪製
`swDrawBase` 加了 1.4× 放大並任其裁切；實機回報滿框字（春）溢出米字格。移除 1.4×
後又暴露：抄經彈窗走另一個建構器，反而偏小。本弧把「範字大小」從各自為政的權宜，
統一成一條**墨跡實框正規化**契約，並順帶根治收工工具鏈一個靜默沿用舊 commit 訊息
的老坑。

## 決策 1：範字大小用「墨跡實框正規化到固定佔比」，不用硬放大或裁到容器框（§64）

**觸發**：實機兩症狀——稿紙彈窗滿框字溢框（5fm）；移除放大後抄經彈窗偏小（5fn）。

**根因**：三種呈現面各用一套「大小」策略且互不一致：
- `swDrawBase` 對所有範字統一 1.4× 放大＋任其裁切→滿 EM 框字溢框。
- `swBuildCellRefImg`（稿紙/字帖…）視框＝整個 EM 2048 框，四周留白因字而異。
- `swBuildSutraRefImg`（抄經）視框＝整個字格 rect，而描紅字只佔字格約 6 成、格子非正方。
- 獨立頁 `drawReference` scale＝`min(w,h)/EM_SIZE`，整個 EM 框鋪滿→滿框字頂邊。

**選項**：

| 編號 | 方案 | 優點 | 缺點 |
|---|---|---|---|
| A | 每面各量該字**墨跡實框**、正方＋8% 邊距、置中，固定佔 ~86%；共用繪製 1:1 貼滿 | 每字固定佔比、跨面一致；既大又不溢框 | 各建構器要各取墨跡框（座標系不同：格內 getBBox／抄經 getScreenCTM 反矩陣） |
| B | 保留 1.4× 但加「不得超出框」夾制 | 改動小 | 佔比仍取決於「字剛好多滿」、不同字不一致；治標 |
| C | 只改抄經那條、其他不動 | scope 最小 | 各面仍各自為政、下次再分岔 |

**考慮的因素**：跨呈現面一致性（同一個字在五個入口要一樣大）、每字佔比穩定、
最小 scope、不同建構器的座標系差異。

**選擇**：☑ A

**理由**：使用者要的是「範字夠大又不溢框且各模式一致」。只有「量墨跡實框、正規化到
固定佔比」能讓佔比不再取決於該字剛好多滿/多空——硬放大（B）與裁到容器框（C）的
佔比都隨字浮動。A 一條契約套三面：`swBuildCellRefImg` 暫掛回宿主 SVG 量 `getBBox()`；
`swBuildSutraRefImg` 幾何命中該格字形群＋`getScreenCTM()` 反矩陣取 user 座標墨跡框；
`drawReference` 量墨跡長邊填滿 86%。共用繪製 `swDrawBase` 退回 1:1 貼滿、放大常數移除。

**後續驗證**：✅ Playwright 截圖，五入口的春/一/觀/在/世皆填滿 ~86% 置中不溢框、無
page error。

## 決策 2：改共用下游要巡「所有」上游消費路徑（§64 後半）

**觸發**：5fm 只驗了走 `swBuildCellRefImg` 的四模式就收工；抄經走
`swBuildSutraRefImg` 被漏，隔一輪才被實機回報偏小（5fn）。

**根因**：「改共用繪製 `swDrawBase`（拿掉 1.4×）」影響**所有**餵它 refImg 的建構器，
但只清點了其中一支。一個病、多個入口。

**選擇**：☑ 改共用下游時，先 grep 出所有呼叫/餵入該下游的分支，逐一驗證或修正。

**理由**：共用點的改動半徑＝其全部消費者；漏一支就是「別人好、它獨壞」的分岔 bug。
本案兩個建構器（cell／sutra）＋一個獨立頁 renderer，三支都要套同一契約才收斂。

**後續驗證**：✅ 5fn 補齊抄經路徑後五入口一致。

## 決策 3：守門測試鎖「不變式」；改實作同批更新守門並註明「意圖不變」（§66）

**觸發**：本弧三次被守門咬紅——`test_5fb` 鎖 `REF_SCALE = 1.4`、`test_5eq` 鎖
`_filledIds = ["sutra-glyph-reference", "sutra-trace"]` 及其否定斷言。保留意圖的重構
把這些字面字串換掉，守門就誤紅。

**選擇**：☑ 守門盡量鎖不變式（存在性/順序/行為）；真鎖實作字串就改實作時同批更新、
commit 註明「意圖不變、僅結構更新」。

**理由**：鎖字面寫法＝把「怎麼寫」當契約，重構必踩。5eq 守門改為斷言 `_order` 陣列的
**順序**（骨架 index 大於填實層 index）＋`break` 存在，即鎖住「填實優先、骨架殿後」的
不變式，而非某段字面。承 §61（動版位先 grep 歷代版位斷言）：改前先 grep 被改符號在
tests/ 的出現，把守門更新一起排進本次改動。

**後續驗證**：✅ `test_5fb`／`test_5eq`／全量 `test_sutra.py`(210) 綠。

## 決策 4：已知脆弱的慣例升級成自動閘門，不留 note 靠紀律（§65）

**觸發**：收工檢查.bat 以檔名字典序挑 commit 訊息檔當「最新」，沒放當班檔時靜默沿用
舊訊息。此坑 7/19（5er）踩過、僅留 WORK_LOG note，7/22 復發。

**選項**：A 加當日新鮮度守門（fail-open）／B 改按 mtime 挑／C 用後歸檔已用訊息檔。

**選擇**：☑ A（B 因 mtime 也被動過而不可靠、且無法治「沒放當班檔」；C 需搬 180 檔
backlog、且訊息檔為 gitignore 本非版控）。

**理由**：靠紀律的教訓會復發；把教訓變成閘門才治本。A 讓「遺漏」從『靜默用錯』變
『明確中止』，且 fail-open——取不到日期就跳過守門、絕不誤擋合法提交（守門是助手非
安全閘）。

**後續驗證**：✅ 5fn 收工即自帶實測（挑到當日 `2026-07-22_02.txt`、放行、訊息正確）。

## 沒做的決策（明確擱置）

- **收工檢查.bat「用後歸檔」**（同日第二次未放新檔的重複提交防護）：罕見，且需搬
  180 檔 backlog；當日新鮮度守門已治跨日主病灶，暫不做。
- **抄經與其他模式合併成單一建構器**：兩者取墨跡框的座標系不同（格內 getBBox vs
  抄經整層需幾何隔離＋getScreenCTM），強合併反增耦合；各自套同一「正規化契約」即可。

## 學到的規則（→ PRINCIPLES §64–§66）

- **§64**：多個「同一物件的呈現面」要一致，用同一條**墨跡實框正規化**契約（量 ink
  bbox、正方＋固定邊距、固定佔比），別用硬放大＋裁切或裁到容器框等隨字浮動的權宜；
  且改共用下游要巡**所有**上游消費路徑（一個病、多個入口）。
- **§65**：已知脆弱的慣例要升級成自動閘門、別留 note 靠紀律；自動挑「最新/預設」配
  fail-open 新鮮度守門，讓遺漏變明確中止而非靜默用錯。
- **§66**：守門測試鎖不變式（存在/順序/行為）不鎖當時寫法；真鎖實作字串就改實作時
  同批更新守門、commit 註明「意圖不變」。
