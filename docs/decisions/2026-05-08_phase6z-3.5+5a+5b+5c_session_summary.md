## 1. 主要決策

### 1.1 Auto-fill → User-place 架構轉折（6z-3.5）

User feedback「目前看起來是自動填滿，後續會如何操控這些元素的疊加方式」 直擊 6z-3 MVP 不是 final UX。對位 v0.3 §1 主流程「**從基底元素開始畫疊加**」。

**決策**：
- `_placedUnits[]` 取代 grid auto-fill 為 source of truth
- Click → place 單一 unit；點兩下定方向；R 鍵 repeat 3 次
- `viewportToTileLocal(x, y)` inverse transform 處理 click on rotated/panned canvas
- 既有 `buildTangle(area, density)` grid 函數**保留** — 6z-3.5.X 可作 fallback / preview thumbnail

### 1.2 Per-unit local Pseudo-3D（6z-5a）

v0.3 §4 設計，每個 placed unit 有自己的 `pseudo_3d.depth_dir + depth_degree`。對 unit center (ucx, ucy) 局部 perspective transform — **非全 tile 透視**。

**決策**：
- 4 方向：forward (foreshortening) / backward (擴張) / left (剪切右厚) / right (剪切左厚)
- Sticky state — set once + new unit inherit
- 鍵盤 ↑↓←→ via `KEY_DIR_TO_PSEUDO3D` translate 接 `_actionHandlers["pseudo3d-dir"]`
- 數學: SCALE_COEF = 0.5 (forward/backward ±50%), SHEAR_COEF = 0.4 (left/right)

### 1.3 Curve mode 雙維度（6z-5b/c）

v0.3 §4.1 L-stick 4 軸 deformation curvature。對稱於 depth_dir 加第二維度。

**決策**：
- Pure module 預埋全 4 軸 (high-mid / high-sides / left-high / right-high)
- 6z-5b UI 暴露軸 1 only → 6z-5c 加 HTML +3 button 解鎖剩 3 軸（JS 0 改動）
- Pipeline compose: `spec → depth → curve → render`
- y-shear only — ORB / DOT 半徑保持不變（vs depth forward/backward 的 r scale）

### 1.4 §3.14 SOP dogfood（5/8 開始）

Personal-playbook 第十三次修訂加 §3.14 Cowork 寫檔工具 corruption SOP。從 5/8 起：

- 4 個 decision log 全用 Python list-of-strings + `\n.join` + `newline='\n'`
- 寫完即三件套 verify (`wc -l` / `tail -3` / `xxd | tail -2`)
- 全部 0 mojibake / `0a` LF / 行數無截斷

## 4. 升格成 PRINCIPLES.md 的 patterns

### §6.13 Sticky default + inherit

Trigger：creative tool 有 per-element 設定時。

規則：set once → new 元素 inherit；改 sticky → 同步 latest；old 元素 non-destructive；reset 斷 chain。

對位：§6.9 product launch 預設 vs §6.13 continuous creation 預設 — 兩個不同 user journey 點。

Instances 已累積：6z-1.2 config (char/mode/tile_size) + 6z-5a depth + 6z-5b curve = 3 instances → 升格。

### §6.14 Multi-axis enum + class-based wirable selector

Trigger：feature 多個 discrete options + 想漸進 ship。

規則：
1. Pure module 預埋全 enum + Node test cover all
2. HTML class + data-attr selector
3. JS class-based addEventListener auto-wire

結果：解鎖剩餘 option = HTML +1 button、JS 0 lines。

Instances：6z-2 旋轉 (data-deg) / 6z-2.2 pan (data-pan) / 6z-3 tangle radio (name=) / 6z-5a depth (data-dir) / 6z-5b curve (data-curve) — 5 instances → 升格。

6z-5c 解鎖 3 軸 10 min 完工是 §6.14 最強 demonstration。

## 5. 為何 4-strike pattern 沒觸發

前段 (5/7-5/8 早) 累積 5 次「ship → user E2E catch issue → patch」。但 5/8 晚段 4 commits **沒觸發任何 visual bug catch**。原因分析：

1. **Pure helper Node test 對齊數學** — 6z-5a 21 cases + 6z-5b 19 cases cover 邊界 / identity / inverse / 4 軸對等。視覺 compose 大概率對齊
2. **對稱模板** — 6z-5b 鏡像 6z-5a，認知負擔低、bug 風險低
3. **預埋 enum** — pure module 全 4 軸實作 + Node test cover all、解鎖 UI 不破邏輯
4. **Sticky state 是 acquisition-friendly default** — 沒踩 D-C 強紀律弱預設陷阱、user 直覺對齊

**不代表沒視覺 bug** — 只代表「**前期紀律累積到減 bug 出現頻率**」。下次 user E2E 仍可能 catch（對位 memory `feedback_visual_render_verify`，4-strike pattern 不假設停）。
