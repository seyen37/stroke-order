# 決策紀錄 2026-07-13（第四弧）：5dg 鏤空字實測修正＋5dh 禪繞互動大改版

對應 PRINCIPLES §14。0.14.177 → 0.14.179，pytest 1676 → 1680、
node 125 → 129。兩輪皆使用者實測回饋驅動（實物照片／八項 UX
規格），QODA 各一回（5dg 三案定 B；5dh 規格即 sign-off）。

## D1. 工法慣例編進演算法結構，不靠後驗檢查（5dg）

「直筆中段不截斷、切口在轉折/交接處」不是切完再檢查的規則，
而是候選集的定義：截斷候選＝孔洞邊界的**轉角頂點**（RDP 後方向
變化 ≥45°），直線段從一開始就不在候選集裡。約束由結構保證＝
零誤判、零修補迴圈；退化情境（圓孔無轉角）走明確降級（十字），
不是讓主演算法變複雜。

## D2. 領域知識的來源是實物樣本，依據要入 REF（5dg）

「切口該在哪」教科書不會寫——使用者的字模實物照片與 speedprint
教學才是規格。提煉出的規則（轉角截斷、多點支撐、粗體防斷）與
出處一起寫進 REF_ANALYSIS_STENCIL.md：日後改演算法時能回查
「為什麼當初這樣定」，而不是對著程式碼猜。

## D3. 衍生過程中的歸屬以初始快照為準（5dg）

對稱雙連筋要問「這個字件已經有幾條筋」——連筋畫上去之後元件
就融合了，事後數不出來。解法＝進迴圈前先拍 labels0 快照，橋的
錨點記在**原生元件**帳上。凡是「邊做邊改拓撲」的演算法，統計
帳都要記在初始快照上。

## D4. 幾何演算法的適用域要跟資料共同演化（5dh）

5df-4 的半平面裁剪假設區段是凸的——當時成立。5dh 曲線切割一
出現，切出的半塊就是凹的，半平面裁剪對凹形**靜默給錯答案**
（多塊連橋）。正解＝換成圍籬剖分（splitRegionByPolyline，
邊界順向鏈＋圍籬內段），凹凸通吃；直線切降為其包裝、舊 API 與
測試全數保留。資料形狀升級時，要盤點所有對舊形狀有隱含假設的
演算法——它們不會報錯，只會錯。

## D5. 不確定的幾何情況拒絕，不猜（5dh）

圍籬與邊界的交點數是切割合法性的完整判準：恰 2＝合法；0＝沒
穿過；>2＝彎過頭來回穿越。>2 的情況硬切會產生自相交多邊形——
選擇回報「穿越 N 次」拒絕並讓使用者重調曲率，附面積守恆 ±2%
自檢當第二道閘。幾何運算寧可顯式失敗，不可靜默出怪形。

## D6. 多階段滑鼠互動＝顯式狀態機，事件疊發在狀態機裡吸收（5dh）

「點起點→預覽→點終點→調彎→雙擊定案」用 `_splitState.phase`
顯式建模。關鍵細節：dblclick 必然自帶兩次 click——把「phase 2
的單擊」定義為 no-op，疊發事件就被狀態機自然吸收，不用 setTimeout
去猜「這是單擊還是雙擊的前半」。mousemove 高頻重繪用 rAF 節流。

## D7. 狀態保留的正解是「失效條件表」，不是「都清掉」（5dh）

「模式切換要保留編輯」逼出失效矩陣：每模式各存一份暫存
（_regionStash）；字形重載→只失效 hollow（bg 與字形無關）；
紙磚尺寸變更→兩者皆失效（座標系變了）；「清除區段」→使用者
顯式清空。逐事件問「這份狀態的前提還成立嗎」，而不是圖省事
全清——省事的代價是使用者的編輯成果。

## D8. 檔位參數連續化＋UI 圖示復用生產碼（5dh）

密度兩檔（medium/high）換成連續 spacing＝f(區塊短邊)：內容
尺寸跟載體尺寸掛鉤，窄筆畫元素自動縮小。順手讓 `_spacingFor`
接受數值（enum 語意不變）——同一個開口立刻養出第二個消費者：
縮圖鈕直接跑生產 builder 畫 36px 預覽，圖示與實際輸出同源、
永不漂移（不畫第二套手工圖示）。
