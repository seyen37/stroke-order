## 弧一：X1 筆順分解圖——借鏡的核心物件原生化

第四份借鏡（筆順合併自動插圖作業單產生器）給了第一份 W0 田野證據：老師
的工作流是「生字列表 → 筆順分解圖＋插圖 → Word」，動機是省筆順字型的錢。
X1 把老師從外站抓的那個東西原生排出來：`/api/steps` 每字一條「第 N 格畫
到第 N 筆」，已寫淡灰＋當前濃黑（**灰階可辨鐵則**——刻意不沿用 gif 的
紅色 highlight，`#c33` 灰階後反而比已寫的淡）。

踩點：序號沿用 W2 全形步進——noto_hei 數字是比例寬，「10」排成「1␣0」，
斷言全綠、**放大產圖才看見**（§96 第四次生效）。

## 弧二：R3 手寫字型——「向上」輸出的第一次

FANGCUN 評估的差異化殺手鐧，等了九天等到引擎（R1a）成熟：user_dict 手寫
軌跡 → `flesh_character` seam（零行為變抽出，因為字型需要**環向**、
even-odd 攤平契約給不了）→ signed area 明確定向 → fontTools 組 TTF。
兩層驗證（§95.1）：fontTools 回讀＋ **FreeType 真渲染驗「口」字碗留白**
——環向錯只有真渲染看得出。字集只含寫過的字（sign-off）：.notdef 是
特性不是缺陷，著作權歸書寫者進 name table。

## 弧三：B ±δ——小輪，但撞見一個要立規的坑

向量域雙向粗細微調（XOR 重建繞開 Jordan 巢狀、光柵化前施作避開 2px 量化）。
中途發現：**R1b 量的 ±20 EM「安全區」是楷書級筆寬的**——noto_hei（粗
黑體）在 +20 就黏合「歡」（3→1 件），等於楷書 +40 才發生的事。停下重
規劃：夾限保留、措辭全改「楷書級實測範圍」、noto_hei 實測值釘成已知答
案樁。

**→ §98：引用自己先前的量測數字前，先驗量測條件是否仍成立**（字源、
尺度、環境變了沒）。§93 管「量的當下」，這條管「引用的當下」。

## 弧四：R2 spike——緩議也是完成

三量測：缺口＝筆順鏈 9k → CNS 95k 的筆順幾何（真實但窄）；授權自由
（glyphwiki robots 拒抓、如實記錄、改引 Mozilla 收錄原文）；合規取得只
剩 dump 子集打包（10+ MB 永久體積）＋KAGE 解析器維護＋筆順非教育部標準。
與 T3 同構：**授權可、技術可行 ≠ 值得付永久成本**，需求端零證據 → 緩議。

但這次比 T3 多走了一步：ADR 裡不只留量測數據，還鋪了**直接動工路徑**
（五步，不必重做 spike）和**自動蒐證建議**（筆順鏈 404 記「缺字請求」
計數——讓需求證據自己長出來，不用人猜）。

**→ §99：緩議是一等結案**——翻案條件要可觀測（最好儀器化自動蒐證）、
路徑要鋪到能直接動工。「等需求」不是被動等。
