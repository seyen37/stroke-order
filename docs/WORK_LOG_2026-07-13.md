## 六、5da：OpenCV pin 升 4.11——WASM init 懸掛之謎破案（0.14.167）

backlog「家用機 OpenCV 驗證」意外變成破案輪。Chrome MCP 對照
實驗鏈：

1. 家網 jsDelivr 168ms 暢通 → **確認非校網**（校網會靜默丟包）
2. 正式 worker 管道卡「WASM 初始化」→ 發現分頁在背景
   （visibility: hidden）→ 請使用者切前景排除節流變因 → **仍卡**
3. 精準定位：blob 對照組 `importScripts` 342ms 完成、`await cv`
   永不 resolve——卡點不是腳本執行、是 **WASM runtime init**
4. 微型 WASM 模組主執行緒/worker 皆秒過 → 非 WASM 封鎖
5. **A/B 實錘**：@techstark/opencv-js 4.9.0-release.3（現行
   pin）20s TIMEOUT；4.11.0-release.1 同機同管道 **759ms 完整
   就緒**（cv.Mat ready）

**結論：4.9.0 build 的 WASM runtime init 與新版 Chrome（149
實測）不相容。** 先前判給「受管理校園電腦環境層」的懸掛，極可
能一直就是這個版本不相容——當時的 blob「成功」樣本可能只驗了
importScripts 返回、未驗 cv ready。

修法：
- pin 全面升 4.11.0-release.1（`_OPENCV_VERSION`/`_OPENCV_CACHE_FNAME`
  單一事實源，server/engine/fetch_vendor 三處共用）
- **快取檔名帶版本**（opencv-4.11.0.js）——pin 升級自動失效
  舊快取（Render 燒入檔與本機 ~/.stroke-order/vendor 都適用）
- docs.opencv.org 退出兩份清單——實測只掛 4.9.0/4.13.0
  （4.11.0 回 404），且資料中心 403（5cl）、校網靜默丟包；
  §8.2「實測不存在的 URL 不入 pin 清單」再次應驗
- jsDelivr/unpkg 4.11 皆實測 200（11.4MB）；?v=160

附帶更正：README version badge 自 0.14.164 起兩輪漏更新
（5cy/5cz 只改了 tests badge）——本輪校正並記入收工檢查慣例：
**兩顆 badge 都要對**。
