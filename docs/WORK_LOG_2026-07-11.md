## 二、本日學到的規則

### CJK 一律描邊、`<text>` 只放 ASCII（再度驗證）
節氣日期提示原寫「約 2/4」，「約」在無 CJK 字型主機（cairosvg → PDF）變
豆腐字。與 5bv mark_renderer="polyline" 同源教訓：凡會經過 server-side
rasterise 的 CJK，一律走 char_loader 描邊；`<text>` 保留給數字與拉丁。

### 慢渲染 API 測試 → stub loader，正確性由 exporter 層扛
全頁 118 字真實渲染 40-60s，不入測試。API 測試 monkeypatch `_load` 驗
路由與組版；glyph 正確性由 exporter 單元測試＋視覺驗證覆蓋。乘法表／節氣
只有 11／25 個相異字，exporter 內建 memo loader，真實渲染 0-4s。

### 協作沙箱掛載同步會「前半新後半舊」
Windows 側 Edit 後沙箱 mtime/size 不更新 → Python 沿用舊 .pyc、檔案讀取
被舊長度截斷。解法：`git archive HEAD` 建乾淨副本＋程式化重套修改再驗證；

## 二之六、第六批（同日續）：5br 布章排字重疊修正

user 線上實測回報：80mm 布章放 4 個 22mm 字全部疊在一起。根因：
`_layout_text_positions` 直排邏輯把字心均勻撒在可用寬度，從未檢查
字心距是否小於字寬（4×22mm 案例字心距僅 12mm）。

修法：新增 `_fit_char_size()`（裝不下時自動縮字，上限
w/(n×1.08+0.3)）＋字心距下限 eff×1.08＋統一置中公式；layout 回傳
`(positions, 有效字大小)`，SVG／polylines（G-code/DXF）兩個消費端
同步用有效字大小繪製。空間充裕時位置與舊公式完全一致（回歸零差
異），擁擠時自動縮字排開。+4 tests（重疊場景／寬裕不變／單字／
弧排 clamp）。

附帶發現（未修）：布章 cut SVG 的字形 stroke-width 在 scale 變換
下縮小 118 倍，cairosvg 端渲染成隱形髮絲線（瀏覽器預覽正常）。
記入 followup。

## 二之十一、第十一批（同日續）：5cc 布章髮絲線（backlog 清償）

5bq 輪掛帳的 cairosvg 隱形字形，根因確認：字形群組
`scale(size/2048)` 讓外層 stroke-width(mm) 縮成 0.003mm 髮絲線。
瀏覽器反鋸齒讓它「看起來還在」是假象——雷切軟體與 cairosvg
光柵化都會照規格把它變不見。

- 修法：三個 `_char_*` 函式加選配 `stroke_width_mm`，內層 g 補回
  stroke-width = w/scale（非等比取幾何平均）；只有布章 render
  傳值——印章／表格頁等 8 個填色型消費者不傳＝輸出位元組不變
- E2E（沙箱 cairosvg 光柵化前後對照）：字形區暗像素 **0 → 248**
- test_patch.py +3：補償值結構檢查／無參數輸出不變（保護零回歸）
  ／cairosvg 像素級可見性（importorskip）
- 教訓：**「瀏覽器看得到」不等於「光柵管線看得到」**——描邊型
  SVG 進 scale transform，線寬一律要問「有效 mm 是多少」。
