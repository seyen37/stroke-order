# stroke-order 全站初次使用者體驗稽核報告

- **日期**：2026-07-23　**版本**：0.14.264（本機完整建置實測）
- **方法**：以 Playwright 模擬初次使用者，13 個模式全部「進入→輸入→產生→檢視結果」實際操作，另測 3 個獨立頁（手寫卡片／筆順練習／公眾分享庫）與逐字手寫視窗；共 35 張全頁截圖、按鈕清單逐模式盤點。全程 **零 JavaScript 錯誤**。
- **環境限制（先聲明，避免誤判）**：沙箱裝不到教育部楷書/思源黑體（字型狀態 0/5）與 CDN 的 hanzi-writer——受影響的觀察已標註〔環境〕，需在正式站複驗；但「缺字型時的錯誤呈現方式」本身仍是有效的體驗觀察。

---

## 一、逐模式測試報告

### 書寫練習群

**1. 單字模式（預設落地頁）** — ⚠ 最需要改
- 初始畫面右欄「筆順預覽」是一個大空框＋三顆現在按了沒用的按鈕（播放筆順/互動測驗/重置）；下方「下載」整塊空白、「字元分解 (無資料)」——**初次使用者第一眼看到的是三塊空區**。
- 〔環境〕hanzi-writer 載入失敗時，錯誤只出現在**頁面最底部的「診斷資訊」**，預覽框保持空白——使用者只會覺得「按了沒反應」。錯誤應緊貼「載入 / 重繪」按鈕顯示。
- 按鈕命名「載入 / 重繪」與其他模式的「產生◯◯」不一致。

**2. 字帖模式** — ✅ 佳
- 流程直覺：字串→產生字帖→預覽正確（主字＋ghost＋空格三層如實呈現）；「自動依層數配置」提示列是好設計。
- 小議：「部首家族」下拉＋「⬇ 帶入家族字」兩件並排、術語密度高，初次使用者難以理解；可加一句範例文案。

**3. 稿紙模式** — ✅ 佳
- 「一頁容納：300 字…您輸入：24 字 ✓ 一頁內可放下」的即時計算列是全站最好的回饋設計之一。直書排版結果正確。

**4. 筆記模式** — ✅ 佳（同上有容納計算列）
- 設定項較多但分行清楚；「保留塗鴉區」等進階項有行內說明。

**5. 信紙模式** — ✅ 佳
- 署名/日期/對齊等選項豐富、預覽正確。設定列數最多（頁高 1457px），但各列有標籤對齊，尚可接受。

**6. 抄經模式** — ✅ 全站主力，體驗最完整
- 分類/搜尋/經典管理、頁碼導覽、產生預覽＋三種下載、狀態列「✓ 完成（點格子可逐字手寫）」——動線清楚。
- ⚠ **逐字手寫視窗兩個互動缺陷（實證）**：①按 **Esc 關不掉**（無鍵盤路徑，只能點 ✕ 或送出）②視窗開著時**切換模式不會自動關閉**，殘留蓋住新模式的設定區——按鈕邏輯衝突的實例（背景的模式已換、前景視窗還停在上一件事）。
- 視窗內「送出並關閉」用紅色＝與全站「紅＝主要動作」一致，但與「紅＝危險」的通用直覺相衝（見整體建議 #1）。

### 製造切割群

**7. 塗鴉模式** — ✅ 空狀態全站最佳實踐
- 預覽區明確寫「(選擇圖片後按「產生塗鴉」以顯示)」——**這句話應該推廣到所有模式的空預覽區**。

**8. 布章模式** — ✅ 佳
- 加入→產生預覽→黑線裁字/紅線寫字圖例清楚；平鋪計算列（每 patch 約可放 2 字｜A4 最多 12 個）回饋好。

**9. 印章模式** — ✅ 佳（選項最多但分區有色帶）
- 尺寸建議列（業界 1 字推薦尺寸）、3 字自動補字範例（王小明→王小明印 2×2）都是好設計。「↻ 全部歸零」在最上方、與「+ 加入」相鄰——重置類與建構類相鄰，建議拉開距離。

**10. 鏤空字模式** — ⚠ 錯誤呈現佳、但失敗後留白
- 〔環境〕預設字型思源黑體未安裝→產生失敗；紅字「失敗：無可用字形（skipped: [...]）——請確認字型檔已安裝或換資料源」**緊貼按鈕、指出下一步**＝錯誤訊息的正確做法（單字模式應學這裡）。
- 失敗後「預覽」區塊只剩一條灰色空 bar 佔位——應顯示空狀態提示句。

### 藝術創作群

**11. 文字雲模式** — ✅ 佳
- 「一整圈需要 36 字（周長 364mm，字大小 10mm）」計算列好；「已放置 36 字（容量 36）」結果回饋好。字底朝內時上緣文字倒立屬「印章風」語意，初次使用者可能以為是 bug——選項旁可加一格小示意。

**12. 曼陀羅模式** — ⚠ 表單過長
- 功能最深（preset/檔案/設計意圖/裝飾層/上傳 Gallery），但設定區高逾 1100px，「產生曼陀羅」沉在最底——初次使用者不知道要捲多深。preset 一鍵套用放頂部是對的；建議「產生」鈕 sticky 或頂部再放一顆。
- 「⬆️ 上傳到 Gallery」與「匯出/匯入」在表單第二列，動作層級（分享）與內容編輯混排。

**13. 禪繞字模式** — ⚠ 密度最高、學習曲線最陡
- 可見按鈕 **59 顆**（全站其他模式 6–12 顆）；Aura/Perfs/Coffering 等音譯術語無解說。有「推薦組合」四鍵（慕卡風…）＝正確的降門檻設計，但被淹沒在中段。
- 〔環境〕字型未裝時紅字錯誤顯示於左欄（位置正確）；字體下拉誠實標示「（字體未安裝）」＝好。
- 建議：右欄改「基本／進階」兩段收合，推薦組合提到最上；紙磚旋轉的 8 顆角度鈕＋滑桿＋「立即回正/上次角度」可收成一列。

### 獨立頁

**14. 手寫卡片（/card）** — ✅ 簡潔
- 右欄「加入」四鍵＋「下載」五鍵分區清楚；底部操作說明完整。
- ⚠「刪除選取框」（紅字）放在「加入」群組內——破壞性動作混在建構群；「清空」（紅字）在下載群內亦同。建議兩顆同歸一個「編輯」小區或視覺隔離。
- 主要鈕為**藍色**（＋文字框）——與主站「紅＝主要」不一致（見整體建議 #1）。頁面下半留白約 40%。

**15. 筆順練習（/handwriting）** — ✅ 剛完成資料區整併，左欄一條龍成形
- 素材→模式→字型→組件覆蓋→我的資料（統計/提交/匯入/清空/匯出）由上而下單欄敘事，佳。
- 小議：右側動作欄「完成本字」下方到頁底留白較大，筆畫/取樣點/耗時統計目前在畫布下方——可移入右欄填補，動作與回饋同欄。
- 主要鈕藍色（完成本字）、危險鈕紅框（清空）＝**這一頁的色彩語意反而是最正確的**，建議全站向它看齊。

**16. 公眾分享庫（/gallery）** — ✅ 空狀態文案佳
- 「目前還沒有任何上傳。到筆順練習累積您的字跡…」有指路＝好。
- 空清單仍顯示「上一頁 1/1 下一頁」分頁列（多餘）；版本標籤本輪已修正為自動同步。

## 二、跨模式一致性總評

做得好的（應保持）：三群分頁＋radio 選模式的資訊架構清楚；「設定在上、預覽在下」全站一致；「↓ SVG／↓ G-code／↓ JSON」下載列命名一致；多個模式有即時容量/尺寸計算列；錯誤大多誠實可見。

不一致的（改善主軸）：

1. **主要動作的顏色語意分裂**：主站紅＝主要（產生◯◯），/card、/handwriting、/gallery 藍＝主要；而紅在 /handwriting 與 /card 又是危險色。同一位使用者跨頁會得到相反的訓練。
2. **產生鈕命名**：「載入 / 重繪」「載入字框」vs「產生◯◯」。
3. **空狀態**：塗鴉模式有提示句、單字/鏤空字留白框。
4. **錯誤位置**：鏤空字/禪繞（貼按鈕，佳）vs 單字（頁底診斷區，差）。
5. **共用控制項位置**（字型風格/資料源/罕用字）每模式出現的位置與順序不同。

## 三、整體規劃改善建議（依優先序）

**P0（互動缺陷，1 輪內可修）**
1. 逐字手寫視窗：支援 Esc 關閉＋點背景關閉；**切換模式時自動關閉**（或改用原生 `<dialog>`，一次拿到三者）。
2. 單字模式錯誤上移：載入失敗訊息緊貼「載入 / 重繪」按鈕（照鏤空字模式的樣式），診斷資訊保留當補充。

**P1（一致性統一，1–2 輪）**
3. 色彩語意全站統一：主要動作＝藍（以 /handwriting 為準），破壞性動作＝紅；逐字手寫「送出並關閉」改藍。
4. 空狀態句全站化：所有預覽區未產生時顯示「（輸入◯◯後按「產生◯◯」以顯示）」；產生前 disable 下載鈕（含單字模式三顆預覽操作鈕）。
5. 產生鈕統一動詞：「載入 / 重繪」→「產生筆順預覽」、「載入字框」→「產生字框」。
6. 破壞性按鈕隔離：/card 的「刪除選取框/清空」、印章的「↻ 全部歸零」與建構鈕拉開或加確認（比照筆順練習清空的二次確認慣例）。

**P2（學習曲線與版面，排入 backlog 逐步做）**
7. 禪繞字右欄改基本/進階收合、推薦組合置頂；曼陀羅「產生」鈕 sticky。
8. 共用控制項（字型風格/資料源/罕用字）固定成同一條「共用列」出現在各模式相同位置。
9. 單字模式初始改示範字自動載入（例：永），三空區在載入前先收合；/gallery 空清單隱藏分頁列；/card 縮短底部留白。
10. 文字雲「字底朝內/朝外」加小示意圖；字帖「部首家族」加一句範例文案。

**建議節奏**：P0 一輪（建議代號 5fp）、P1 兩輪（5fq 色彩+命名、5fr 空狀態+隔離）、P2 依使用頻率排。每輪照現行 SOP：實作→E2E→寫回→收工檢查.bat→部署驗收。
