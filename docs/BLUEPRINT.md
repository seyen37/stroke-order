```

                    教育部辭典(6,028) ─ 五份字表 ─ user_dict手寫 ─ 骨架長肉引擎

                    立體字popup ─ 禪繞 ─ 曼陀羅 ─ 卡片 ─ 手寫字型handfont ─ QR ─
                    多頁PDF管線 ─ G-code/DXF/SVG/GIF/TTF
     ↓
介面層 web/         104 端點 ─ 16 模式 UI ─ /teach 教學頁 ─ 分享庫 ─ 出口信封
```

**判讀**：這是一個「以 IR 為腰」的沙漏架構——上面 19 個來源、下面 35 個
出口，全部通過同一個中間表示。**這個腰是專案最大的架構資產**：新來源自動
獲得所有出口、新出口自動吃所有來源（R3 手寫字型能半天落地，正是因為
user_dict 早就進了 IR）。

## 2. 目標與定位（重新確認）

### 2.1 一句話定位

**「中文字元的向量筆跡引擎」——把字變成可教、可寫、可做的東西。**

三個動詞就是三條產品線：可**教**（教學紙材）、可**寫**（機器人/手寫）、
可**做**（雷雕/紙藝/實體）。

### 2.2 護城河（為什麼是我們）

1. **筆順幾何**：g0v 教育部標準楷書筆順原生渲染——同類工具（twpen 抓圖、
   Gemini Canvas 產生器、FANGCUN）都沒有或要抓外站。
2. **實體輸出鏈**：G-code/DXF/連筋/殘腔判準——字型工作室不碰的領域。
3. **使用者手寫資料**：user_dict → 手寫字型，FANGCUN 評估認證的獨家。
4. **治理紀律本身**：99 條原則＋109 份 ADR＋2,228 測試——單人專案能持續
   快速出貨而不崩壞的原因，這是隱形資產。

### 2.3 明確不做（既有 ADR 的定位鎖，本文重申）

不做 LLM 內容生成（§87）、不做完整字型工作室（與 FANGCUN 正面競爭）、
不自動抓網路圖片（版權）、不打包低覆蓋率資產（T3 22.4% 教訓）、不給假
難度軸（W4 誠實標示）。

## 3. 運作模式分析：什麼在起作用、什麼是隱憂

### 3.1 起作用的（保持，不要動）

- **借鏡→評估書→QODA→分輪落地**的節奏：四份借鏡證明有效——排序預測
  四之四命中（§97 retrospective）。
- **收工檢查.bat 單一閘門**：fetch-first → 全測 → badge → 累積式訊息檔
  commit。跨機同步事故自 §69 後零再犯。
- **風險註記→守門測試**的生產線（§97）與**零回歸鎖**（opt-in 預設關、
  逐位元組相同）。
- **雙軌記憶體**（預設不付代價）與**誠實降級**（缺料 503/留白，不裝懂）。

### 3.2 結構性隱憂（按嚴重度排序）

**A. 驗證真空（最嚴重，非技術）**：2,228 個測試證明「做的東西是對的」，
**零個使用者回饋**證明「做的是對的東西」。四份借鏡都是外部作品的間接
證據。整個路線圖的下一步都押在 W0 上，而 W0 六天沒有動靜。

**B. index.html 巨石（3,500 行）**：16 個模式的 UI 全在一頁。JS 已模組化
（18 檔），HTML 沒有——每加一個模式就加一段，衝突面越來越大。5cn/5cs
的 data-* 錨點慣例是止血帶，不是解方。

**C. Render free tier 天花板**：512 MB（W1 配額模型的存在理由）、冷啟動
（wakeup overlay 的存在理由）、單機。目前夠用，但任何「多位老師同時用」
的未來都會先撞這面牆。**這是刻意的節儉，不是疏忽——升級的觸發條件要
先定好**（見 §8 gate）。

**D. 單人巴士係數**：治理文件把知識外部化得很好（這正是它的目的），但
部署金鑰、Render 帳號、GitHub release 字型都繫於一人。

**E. 測試套件耗時**：全套 3–3.5 分鐘，仍可忍；按今天的斜率（一日 +223），
半年後會變成 8–10 分鐘的收工稅。分層（fast/slow 標記）是遲早的事。

**F. 資料授權矩陣的複雜度**：OFL、CC BY-ND 3.0 TW、g0v、MIT、BSD 各有
義務。licenses/ 治理目前正確，但每加一源就多一格——§88/§91 的教訓證明
這裡最容易錯。

## 4. 可行性分析：三條產品線各自的路

### 4.1 教學線（可行性最高、證據最缺）

功能已齊：字帖（PDF/釋義/分級/注音）、分解圖、教學單、QR。缺的全是
**採用**：老師知不知道、用不用得順、Word 是不是硬需求（X2）。
可行性瓶頸＝觸達與回饋，不是技術。

### 4.2 Maker 線（原生 DNA、小眾深耕）

字模七風格＋字重軸＋±δ、G-code/DXF、立體字、連筋工程。使用者是作者
本人＋潛在同好。可行性瓶頸＝這個社群小，適合作為「作品展示驅動」的線
（做出漂亮的實體作品→社群分享→帶流量），不適合做成長引擎。

### 4.3 個人化線（剛萌芽、情感價值最高）

手寫字型是「寫字工具→字型生態」的第一次向上輸出。天然的分享動機
（「這是我的手寫字型」）讓它成為三條線中唯一自帶傳播性的。可行性瓶頸＝
手寫輸入的品質與門檻（要寫多少字才「像一套字型」、筆壓/連筆的擬真度）。

## 5. 架構與設計方向的重新思考

### 5.1 維持的架構決定（想過了，不改）

- **IR 沙漏不動**：它是複利的來源。任何新能力先問「怎麼進 IR / 怎麼從
  IR 出」，不開旁路。
- **單體 FastAPI 不拆**：104 端點聽起來多,但無狀態、共享一套字形快取，
  拆微服務只會把記憶體預算切碎。規模觸發條件（§8 G3）到達前不動。
- **資料隨 repo / 字型隨自家 release**：離線可用、零執行期外部相依
  （§68/§86）是根治過兩輪的痛，不回頭。
- **不引入前端框架**：18 個 vanilla ES modules＋parity 測試運作良好；
  引入 React/Vue 是為了解決「協作規模」的問題，單人專案沒有這個問題。

### 5.2 要改的方向（新決定，附理由）

**D1 前端 HTML 分片（治隱憂 B）**：index.html 依模式拆成 `<template>` 或
build-time include 的片段檔，載入序與 id 錨點契約照舊（test_web_layering
既有守門直接沿用）。理由：巨石的成本是「每輪都付一點」的慢稅，趁 16 模式
還數得清時拆，成本最低。**不是重寫**——純機械搬遷＋守門，兩輪內完成。

**D2 需求儀器化（治隱憂 A 的一半）**：§99 的精神落地成常設機制——
筆順鏈 404 缺字計數（R2 翻案感測器）、各模式使用計數（匿名、無 PII、
localStorage 免登入）。理由：W0 靠「發連結等回饋」是被動的；儀器讓
「哪個模式真的有人用」變成可查的事實，路線圖的 gate 才有數據可判。

**D3 測試分層（治隱憂 E）**：pytest 標記 `slow`（光柵化/PDF/端到端），
收工檢查跑全套不變，開發中可 `-m "not slow"` 快迭代。理由：先鋪標記、
後收利息——等到 10 分鐘才做就晚了。

**D4 教材成品庫（教學線的下一個複利點）**：老師要的不是 104 個參數，是
「三年級第五課的字帖」。在既有分享庫上加「教材範本」分類：一鍵套用
別人調好的參數組合（深連結參數路已有，§74）。理由：把「會調參數的人」
的產出變成「不會調的人」的入口——採用瓶頸的正解。

### 5.3 想過但不做的（留紀錄防重議）

- 改 SPA framework：見 5.1。
- 上資料庫（PostgreSQL）：分享庫 SQLite 夠用到 G3；先動它是過早優化。
- 會員系統/雲端儲存使用者資料：隱私與維運成本 >> 現階段價值；user_dict
  本機制＋匯出入 ZIP 是刻意的設計（資料主權在使用者）。

## 6. 規劃策略與原則（修訂本文時遵循）

這些是從 §1–§99 蒸餾出的**路線圖層級**原則——日常工程原則在 PRINCIPLES，
這裡只放「決定做什麼」時用的：

1. **證據先於建設**：功能齊了就停，把下一步押在使用回饋上；沒有證據時
   寧可儀器化蒐證（§99），不憑想像加功能。
2. **借鏡是需求證據，不是實作藍圖**（§90）：別人的作品告訴我們「有人要
   什麼」，做法自己定——四份借鏡全部如此落地。
3. **複利優先**：優先做「讓既有資產互相加乘」的事（資料在、沒接＞
   新建能力）；W1/W2/X1 全是接線不是新建。
4. **誠實是產品特性**：留白不猜（§87）、標示不誇（W4）、降級可見
   （503＋說明）——教育場景的信任來自這裡，是差異化不是限制。
5. **永久成本要過需求門檻**（§89/§99）：體積、相依、維護面——「授權可、
   技術可行」不構成理由；緩議附翻案路徑是一等結案。
6. **每輪獨立可用**（§90）：路線圖上任何一步做完就能出貨，不做「要三步
   才能用」的規劃。
7. **量測條件隨引用重驗**（§98）：本文引用的所有數字都標了日期與條件，
   修訂時重量，不沿用。

## 8. 實行步驟指引（分階段，各有 gate）

**Phase 0（現在～2 週）：驗證期——不寫新功能**
1. D2 需求儀器化（半天：404 計數＋模式使用計數）。
2. W0 觸達：把 /teach、字帖、分解圖、手寫字型連結發到教師社群（含作業單
   工具作者）；準備一頁「給老師的使用說明」（不是 README，是教案語言）。
3. D3 測試分層標記（半天）。
   **Gate G0**：收到第一批（≥3 人）真實回饋 → 進 Phase 1；兩週無回饋 →
   檢討觸達管道而非加功能。

**Phase 1（回饋後～2 個月）：採用期**
4. 依回饋決定 X2 docx（老師說 PDF 不夠才做）。
5. D4 教材範本庫（分享庫加分類＋套用鈕）。
6. D1 前端分片第一輪（先拆最大的三個模式）。
   **Gate G1**：教學線週活躍 >10 或範本庫範本 >20 → Phase 2；否則轉攻
   個人化線。

**Phase 2（2–6 個月）：成長期**
7. 個人化入門流程（「寫你的名字→得到字型」三分鐘體驗）。
8. D1 前端分片完成；R2 依 404 數據決定翻案。
   **Gate G2**：任一線出現自然成長（非自己推廣帶來的使用）→ Phase 3。

**Phase 3（6 個月＋）：規模期（觸發才做）**
9. **Gate G3（基礎設施升級觸發）**：Render 免費層出現真實 OOM/排隊，或
   冷啟動流失可量測 → 付費層或換平台；分享庫併發寫入衝突 → 評估 DB。
10. 巴士係數：部署文件化到「另一人照文件可完整重建」，金鑰備援。

**執行紀律**：每個 Phase 內仍走 QODA＋ADR＋收工檢查；gate 判定要引用
儀器數據（D2），不憑感覺；跳 phase 要在本文修訂紀錄留一行理由。

## 9. 風險與緩解

| 風險 | 可能性 | 緩解 |
