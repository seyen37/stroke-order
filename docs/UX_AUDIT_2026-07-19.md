## 3. 跨模式共通問題（一致性）

1. **資訊架構扁平**：14 模式（含手寫卡片）一排 radio，O(14) 認知負荷；分群（書寫/製造/藝術）未表達。〔對映規劃書 R9／§6.2，**未處理**〕
2. **主動作命名漂移**：`產生字帖/產生筆記/產生信紙/產生塗鴉/產生文字雲/產生曼陀羅` vs `產生預覽`（patch/stamp/sutra）vs `產生`（stencil）vs `載入/重繪`（single）。同一件事五種叫法。
3. **主動作視覺權重不足**：sutra/stamp 的 action bar 把「產生預覽」跟下載鈕排成等寬同色，主要動作沒被強調。〔對映 §6.3 四級語彙，**未處理**〕
4. **下載鈕三套詞彙＋三套圖示**：`↓SVG(engrave)/↓PDF/↓G-code(laser)/↓分層DXF`（stamp）、`↓本頁SVG/↓全部SVG/↓整本PDF`（sutra）、`⤓SVG(cut)/⤓G-code(裁字)/⤓G-code(寫字)/⤓分層DXF`（patch）、`📥匯出/📤匯入`（mandala）。圖示 `↓`/`⤓`/`📥` 三種、標籤各異。
5. **重置/清除叫法不一**：`重置`（single）/`全部歸零`（stamp）/`清除已放`＋`留白`（zentangle）/`×`（mandala）/`清除區段`（zentangle）。
6. **無基本/進階分層（部分模式）**：single 把進階術語平鋪；反觀 stamp 用 `▶` 收合做得很好——做法不一致。
7. **CDN 失敗＝硬錯誤無降級**：single 的 hanzi-writer 一失敗就整塊 ERROR。〔對映規劃書 §7.3，**未處理**〕
8. **全站一致的部分（值得保留）**：每模式頂端「✎ 罕用字管理 + 字型狀態(x/5)」、紅色實心=主要動作、頁尾資料來源標註——這些是好的一致性基礎。

## 4. 按鈕邏輯與衝突（重點）

### 4.1 主動作被「稀釋」
把「產生」這個唯一主要動作跟 3–5 個下載鈕並排成等重按鈕（sutra/stamp/patch）。初次使用者不知道該先按哪個——**主要動作要在視覺上跳出來**（實心強調色＋固定版位），下載是次要（描邊/淺底）。

### 4.2 導覽與動作混排
sutra 的 `◀前一頁 / 下一頁▶ / 產生預覽 / ↓本頁SVG / ↓全部SVG / ↓整本PDF` 六鈕一排：導覽（換頁）＋生成＋下載三種語意同列。應分「導覽區 · 主要動作 · 下載區」三段。

### 4.3 語意相同、外觀不同（跨模式衝突）
下載 SVG 這件事，在 stamp 是「↓SVG(engrave)」、patch 是「⤓SVG(cut)」、sutra 是「↓本頁SVG」。使用者跨模式時要重新辨識——**同一動作應同一語彙**。

### 4.4 zentangle：開發中介面外露（最嚴重）
- **43 個可見按鈕**塞在一個面板。
- **四套方向控制、同一種箭頭語言、四種意義**：放置（↑上/←左/右→/↓下 圍著 canvas）、紙磚旋轉（0/45/90/135/180/-135/-90/-45 八角）、透視（前↑/後↓/左←/右→）、曲線（中高/邊高/左高/右高）。初次者無法分辨「移動 vs 旋轉 vs 透視 vs 曲線」，全是箭頭。
- **開發者 scaffolding 直接顯示給使用者**：「6z-3.5 user-place: 先選 tangle → 點 canvas 放第一個 → 再點 → R/E 鍵 repeat…」「下一步（後續 sub-phase 解鎖）：紙磚旋轉(R-stick)、切割 mode(□)、tangle 庫(△)、疊加(R1/R2)、pseudo-3D(D-Pad)、草稿系統(○ undo)」——遊戲手把對映與內部 phase 代號是**開發筆記，不該出現在正式 UI**。
- 判定：zentangle 是**未完成的實驗**被當正式模式並列。它拉低整個軟體的「初次印象一致性」。

## 6. 實機操作後的修正（給規劃書）

### 修正 1：優先序對調——UI 一致性（原 §6）升為最高，效能收尾（原 §7 剩 lazy-load）次之
理由：§7 最重的「拆檔」已完成；§6 完全未動且是第一印象痛點。Option A 的 Stage 1 第一步應是「UI 契約」而非「分段載入 PoC」。

### 修正 2：新增「模式契約（Mode Contract）」——把 stamp 的做法系統化成全站規範
每個模式的控制區與 action bar 一律遵循：
- **主動作**統一叫「**產生預覽**」、實心強調色、固定在設定區右下、每模式最多一顆。
- **下載**統一語彙與圖示：`↓ SVG`／`↓ PDF`／`↓ G-code`／`↓ DXF`（需區分時用副標，如 `↓ G-code · 寫字`），排在主動作左側、描邊次要樣式。
- **導覽**（換頁）自成一區，不與生成/下載混排。
- **重置/清除**統一叫「重置」、放工具列、破壞性用紅色＋二次確認。
- **進階選項**一律用 `▶` 收合（抄 stamp），基本欄位才平鋪（修 single）。

### 修正 3：新增「生產環境清理」項（規劃書原本沒有）
- **zentangle**：移除開發 scaffolding 文字（R-stick/D-Pad/phase 代號/操作步驟提示）、把四套方向控制用**分頁或分區＋不同視覺語言**區隔、或在成熟前標「實驗中（beta）」並移出主模式列。
- 全模式 audit 內部筆記/代號是否外露（如「6z-3.5」「字體未安裝」等）。

### 修正 4：更新規劃書現況（§1/§2/§7）
標記「模組化已完成（5er~5fl）」，R8 從「最高」降級為「殘留 lazy-load」，避免規劃書誤導未來的你。

### 修正 5：CDN 降級（承 §7.3，實機驗證有效）
single 的 hanzi-writer 等 CDN 失敗要給友善提示與 fallback（如改用伺服器筆順或靜態範字），不要整塊 ERROR。
