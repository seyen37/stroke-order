# WORK_LOG 2026-07-17

## 5dw：逐字手寫延伸到元素週期表頁（0.14.201）

承 5dp→5dv 抄經深化弧的下弧候選之一（QODA 使用者選「手寫延伸到表格頁」、
範圍拍板「只做週期表」）。

### 需求

逐字手寫（5dt：點抄經預覽格子→手寫自己的字→存 user-dict→取代描紅）目前
只在抄經內文頁可用。把它延伸到元素週期表頁——點週期表的元素格也能逐字
手寫。

### 根因：單一未轉發的旗標

沿資料契約從產生端走到消費端，缺口是一段沒往下傳的參數：

- **前端早已通用**：`sutraRender()` 對任何頁（含 table）都送
  `emit_cellmap:true`，並無條件呼叫 `swAttachPreviewClicks(preview)`
  （綁 `#sutra-cellmap rect[data-char]`→開逐字彈窗）。
- **render_sutra_page 早已會發**：`emit_cellmap=True` 時吐
  `<g id="sutra-cellmap">` 透明點擊 rect，horizontal 方向照發 data-char。
- **斷點**：server.py `page_type == "table"` 分支呼叫 table renderer 時
  **沒把 `emit_cellmap` 傳下去**（body 分支 3917 行有傳、table 分支漏）。
  而週期表頁（5du/§24）本來就重用 render_sutra_page、每格是單一元素字的
  米字格——機制齊備，只差這條線。

### 修法（兩處，零新機制）

1. `exporters/periodic_table.py`：`render_periodic_table_page` 加
   `emit_cellmap: bool = False`，原封轉給 `render_sutra_page`。
2. `web/server.py`：table 分支用 `inspect.signature(render_table)
   .parameters` **能力偵測**——renderer 吃 `emit_cellmap` 就傳
   `req.emit_cellmap`、吃不下就跳過。好處：未來任何新單字表 renderer 在
   簽名加上 `emit_cellmap` 就自動參與，不必回改 server；自繪多字表
   （乘法表/節氣）零影響。不寫死 `if preset == "periodic_table"`。
3. `import inspect`（stdlib）。

### 驗證

- 新增測試 4（tests/test_periodic_table.py）：cellmap 開關（True 含
  `sutra-cellmap`＋data-char、False 不含）／恰 118 個元素 rect（空白格
  不發 rect）／API GET table 頁 emit_cellmap 流通／自繪表（multiplication_
  table）帶 emit_cellmap 不炸（能力偵測守門）。
- 全量 pytest 沙箱 1711 passed / 54 skipped / 0 failed（本輪網路配合、
  無 503；既有 test_5dt_cellmap_flows_through_api 曾遇 transient 503，
  重跑即過，走 body 分支與本改動無關）。
- **Playwright 端到端（真瀏覽器、真 UI）**：選週期表→導到表格頁→真
  `sutraRender()`→118 個 cellmap rect＋SW.positions=118（順序 氫氦鋰鈹硼）
  →點「氫」格→逐字手寫彈窗開、顯示「第 1/118 字・目前：氫」。截圖目視
  確認彈窗與米字格範字。沙箱無遠端字形源，118 罕用字載入吃 503，用 null
  loader 打樁——正好是罕用字無筆順＝data-missing 的真實手寫場景，cellmap
  不依賴字形載入成功。

版本 0.14.200 → 0.14.201；README badge tests 1700 → 1704（+4 皆離線安全，
本機同計）。node 257 不變（未動前端 .mjs）。零新增依賴。

### 收官三件套

本 WORK_LOG＋decisions/2026-07-17_5dw_periodic_handwrite.md＋PRINCIPLES §26。

### 下弧候選（承 5dv 未動者）

逐字手寫延伸到部首/倉頡/注音等其餘單字表（B 案，各補 cellmap 疊層）、

## 5dx：逐字手寫延伸到部首/倉頡/注音單字表（0.14.202）

承 5dw 的下弧候選 B。QODA 使用者選「A：抽共用 helper、三表一輪」。

### 背景：5dw 的兩個複利當場兌現

這三張表（部首 214／倉頡 25／注音 37）都是**自繪** renderer（不像週期表
重用 render_sutra_page），但每格單一字/符號，正好貼合逐字手寫「一格一字」
模型。要落地只需各自吐 `#sutra-cellmap` 疊層——而：

- **後端 server 零改動**：5dw 的 table 分支已用 `inspect.signature` 能力
  偵測轉發 emit_cellmap（§26②）。這三個 renderer 一旦簽名長出
  emit_cellmap，server 自動把旗標餵給它們——**新單字表 opt-in 免費**當場
  應驗。
- **前端零改動**：sutraRender 對任何頁送 emit_cellmap:true＋無條件
  swAttachPreviewClicks，契約是 `#sutra-cellmap rect[data-char]`。

### 做法：抽共用 helper（單一真相源）

三個自繪 renderer 要吐的 rect 格式必須與抄經頁**逐字節一致**（否則前端
parser 接不到）。故在 sutra.py 抽出 `cellmap_rect()`＋`cellmap_group()`
單一真相源，並把 render_sutra_page 原本內嵌那段也改用（零行為變化——既有
sutra cellmap 三測試綠證）。三個 renderer：

- `kangxi_radicals.py`：每格 pos＝enumerate index，214 rect。
- `cangjie_roots.py` / `zhuyin.py`：跨分組全域 cell_pos 計數（內圈 k 每組
  重置），**只對可寫字格發 rect、跳過左側分類標籤帶**（哲理類/聲母…不可
  寫）。25 / 37 rect。

三 renderer 各加 `emit_cellmap: bool = False` 參數＋收集 cm list＋inner
末端 append `cellmap_group(cm)`（畫最後、透明 rect 疊在字上收點擊）。

### 驗證

- 測試 +6：test_kangxi_cangjie.py（部首 214 / 倉頡 25 rect 開關＋標籤字不
  成 rect＋API 流通）、test_zhuyin.py（注音 37＋loader 記憶化不破＋API）。
- 全量 pytest 沙箱 **1717 passed / 54 skipped / 0 failed**（1711→+6）；
  乘法表/節氣（多字格自繪、無 emit_cellmap 參數）維持綠＝5dw 能力偵測正確
  跳過它們。
- **Playwright 端到端三表（真瀏覽器、真 UI）**：選部首/倉頡/注音→表格頁→
  真 sutraRender→cellmap rect 數 214/25/37＋SW.positions 相符→點格子
  （一/日/ㄅ）→逐字手寫彈窗開、current_char 相符。3/3 PASS、零 page error。
  沙箱遠端字形源不可達，null loader 打樁（cellmap 不依賴字形載入成功）。

版本 0.14.201→0.14.202；README badge tests 1704→1710（+6 離線安全，本機
同計）。node 257 不變（未動前端）。零新增依賴。

## 5dy：逐字手寫彈窗兩處 UX 修正（0.14.203，純前端）

使用者實測回饋兩點，皆在逐字手寫彈窗（index.html 內嵌）。

### ① 復原/清空移到米字框外左上

原本 `position:absolute;top:6px;left:6px` 疊在畫布左上角（框內、壓住字）。
改成：畫布區改 flex 直排，`復原`/`清空` 一列放在**畫布上方、框外**、左對齊；
canvas 與「0 筆畫」資訊維持 relative 容器。Playwright 量測確認按鈕
bottom（301.5）≤ canvas top（307.5）、undo_left＝canvas_left＝418＝框外左上。

### ② 清空後送出＝刪除原先儲存的字跡

**Bug**：`swSubmitCurrent` 對空筆畫一律 `return {wrote:false}`（no-op），
所以「清空→送出並關閉」不會動到已存的手寫＝使用者無法藉此清掉。

修法：加 `SW.hadSaved` 旗標——`swLoadCurrent` 預載到既有 user-dict entry
時設 true。`swSubmitCurrent` 空筆畫時：若 hadSaved 則 `DELETE /api/user-dict/
{char}`（404 視為已刪、當成功；端點本就 reset_source_cache，預覽自動還原
原描紅範本）、清 hadSaved、dirty=true；若非 hadSaved（本來就沒存）維持
no-op、不亂送 DELETE。POST 成功路徑補設 hadSaved=true。此邏輯同時套用
上一字/下一字的自動送出（行為一致）。

### 驗證

- Playwright 端到端（真瀏覽器、單程序、temp user-dict 隔離）：預存永→開窗
  hadSaved=true＋預載 2 筆→按鈕在畫布上方→清空（0 筆）→送出並關閉→
  `GET /api/user-dict/永` = **404（已刪）**；無存過的字（國）clear+submit＝
  no-op、GET 仍 404、零 error。截圖目視按鈕已在框外。
- 純前端（index.html），無 Python 變動＝pytest 維持 1710、node 257 不變、
  零新增依賴。版本 0.14.202→0.14.203（badge tests 不變）。

## 5dz：下載檔名友善化（0.14.204）

使用者要下載檔名有意義（先前是 `sutra_1.svg` / `stroke-order-user-dict-
日期.zip` 這種）。兩處規格（經多輪釐清，「字型方格」＝字型風格）：

- **彈窗「⬇ 下載」**（手寫 ZIP）：`{字型風格}_手寫字.zip`（如 `楷書_手寫
  字.zip`）。內容不變（全部手寫）＝匯出一次可匯入任何經文。
- **描紅抄本下載**（本頁SVG／全部SVG／整本PDF）：`{經典}_{字型風格}_
  {手寫|範例}`——該頁/該本**有使用者手寫→「手寫」、否則「範例」**。

### 做法：server 擁有檔名、前端讀 Content-Disposition

檔名要判斷「手寫 vs 範例」，而**只有 server 在渲染時知道**（該頁 SVG 是否
含使用者手寫層 `sutra-trace-user`，見 5dv）。故把檔名邏輯放 server：

- server.py：`_STYLE_LABELS`（kaishu→楷書…）＋`_style_label()`＋
  `_safe_filename_part()`（去 `\\/:*?"<>|`）。
- `user_dict_export` 加 `style` 參數 → `{風格}_手寫字.zip`（無 style 保留
  舊的日期名，向後相容）。
- `sutra_post`：Content-Disposition 改 `{info.title}_{風格}_{手寫|範例}`
  （body/table；封面/迴向另標）；手寫＝`"sutra-trace-user" in svg`。
- `sutra_pdf`：任一頁含手寫層即「手寫」。
- 前端 index.html：`filenameFromCD()`（解 RFC 5987 `filename*`）；本頁/
  全部SVG/整本PDF 改讀 Content-Disposition 當 `a.download`（全部SVG 補
  頁碼避免同名、皆有 fallback）；`sw-export` 帶 `?style=`。

判準：**下載檔名若需依賴「渲染當下才知道的內容」（這裡是有無手寫），就讓
產生檔案的 server 設 Content-Disposition、前端讀它，別在前端硬拼**——前端
拿不到那個事實、硬拼會錯。

### 驗證

- 測試 +4（tests/test_user_dict.py）：匯出帶風格→楷書/隸書_手寫字.zip、
  無風格→日期名、sutra 頁範例 vs 手寫（智慧 loader 樁：user-dict 字走真實
  手寫、其餘 404 免網路）、風格標籤。全量沙箱 1721 passed / 0 failed。
- Playwright 端到端（真瀏覽器 download 事件、temp user-dict、單程序）：
  本頁SVG 範例→存氫手寫→本頁SVG 手寫→彈窗匯出 `楷書_手寫字.zip`→整本
  PDF `元素週期表_楷書_手寫.pdf`，全部檔名相符、零 error。
- 0.14.203→0.14.204、badge tests 1710→1714（+4 離線）、node 257 不變、
  零新增依賴。
