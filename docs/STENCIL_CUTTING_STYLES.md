# 連筋字切割規則與可切換切割風格

> 參考來源：方正大黑連筋（FZDaHei-B02）＋越卓大黑/中隸書/等粗宋_喷漆版
> ＋邯鄲喷漆黑体/喷漆英文（韓紹杰）＋竹米 STENCIL（Google Noto 黑體）
> ＋本專案 5dl/5dm 字模引擎實測。（各字型多為商用/來源不明的字庫，本文件
> 僅**參考其切法**歸納規則，實際打包任何字型前務必確認授權。）
> 目的：把「連筋字怎麼切」的規則寫成可查、可擴充的規格，供日後修正
> 改善鏤空/噴漆字模，以及**加入其他切割字體時新增不同切割風格、提供
> 使用者切換選擇**。
> 版本錨點：0.14.189（5dm）。維護時請同步更新末段「與現行實作對應」。

## 0. 名詞

- **counter（字腔／封閉白區）**：被筆畫完全包住的內部空白，如 口 的中
  空、日 的兩格。物理字模上，counter 是一塊會**掉出來**的料——必須靠
  連筋接回板面才不脫落。
- **連筋（tie / bridge）**：把 counter 接回板面（或外框）的細橋。連筋
  字型＝設計師已把連筋畫進字身的字型。
- **主幹（primary stroke）**：字的結構骨幹，通常是**豎筆**或最長的那
  一筆；切割時保留全長。
- **交叉筆（secondary / crossing stroke）**：與主幹相交的筆，通常是
  **橫筆**；切割時在交接處內縮、讓出缺口。
- **噴漆字模（stencil）**：板留、字挖掉，噴漆穿過字形。counter 是板的
  孤島、要連筋。
- **鏤空字（cutout）**：字即本體＋外框，字的各部件要靠連筋掛在框上。

## 1. 兩類斷點（使用者心智模型的形式化）

實務觀察：噴漆字要被切除／連接的地方很好判斷，**主要就兩類位置**——

1. **四邊框（envelope / frame）**：字的最外圈包圍結構（全包圍字的
   外 囗、或字與外框之間）。連筋接在這裡＝把整個內腔接回外部。
2. **一筆轉折（junction / turn）**：一筆與另一筆的**交接處**，或單筆
   自身的**轉折角**（橫折、豎折）。缺口開在這裡＝把相鄰 counter 接通，
   且因為落在轉角、字形依然可讀。

這兩類就是連筋演算法要偵測的**候選位置**。5dm 的「轉角偵測（孔洞
邊界方向變化 ≥45°）＋近牆軸向逃逸」對應的正是第 2 類；第 1 類（外框）
對應 cutout 模式的「字件→最近框邊輻條」。

## 2. 方正大黑連筋抽出的規則（含實測例）

### 規則 R1：主幹保留全長，交叉筆在交接處內縮

方正「日」是最乾淨的範例：**左右兩豎筆保留全高（主幹）**，上／中／下
**三橫筆兩端都內縮、離開豎筆**成漂浮橫槓——每一格都從橫筆兩側的缺口
連出去。字仍完整可讀（三橫都在，只是不碰豎）。

- 判定：橫豎相交時，保豎（主幹）、退橫（交叉筆）。
- 一般化：兩筆相交，保留**較長／較接近垂直方向**的那筆，內縮另一筆。

### 規則 R2：缺口落在交接角，不落直筆中段

方正「口」：上下橫筆各在**兩端（四個角）**與豎筆脫開，直筆中段完整。
缺口一律貼著轉角。這是可讀性鐵則——中段被切會破字。

- 判定：斷點候選＝孔洞邊界的**轉角頂點**（方向變化 ≥45°），直線段
  永不成為候選。

### 規則 R3：缺口軸向對齊、乾淨矩形

方正所有缺口都是**純水平或純垂直**的矩形間隙（像被內縮的筆畫端），
沒有斜切。斜向缺口在複雜字會糊成蜘蛛網。

- 判定：逃逸方向限上／下／左／右四軸，取最短穿牆者。

### 規則 R4：只穿「近牆」，一個 counter 從最近的牆連出

方正的缺口都開在 counter **緊鄰的那面牆**上，不會穿過整個腔體去對側
開口。缺口寬度 ≈ 該面牆（筆）的厚度或略窄。

- 判定：從轉角往內 2px 仍是墨（牆）的方向才算「近牆」，避免穿越空腔
  鑿到對側遠牆（否則對邊兩轉角會撞同一面牆併成一橋）。

### 規則 R5：連筋深度有限——外 envelope 優先，深層內 counter 取捨

方正對**簡單包圍**（口 回 日 目 月 用 同 向 十 王 申 串）做到完全連通
（0 殘腔）；但對**深層巢狀**（國 3、團 6、圓 5、圖 4、車 4、龜 4、
鑿 6、轡 6）只斷開**外框**、把深處的小 counter 留成孤島。

這是方正的**美學取捨**：斷點越少越好看、越易讀，代價是深層 counter
未連。含意有二：

- 若追求**物理有效字模**（每個 counter 都不掉料），外框連通不夠，深層
  counter 仍需演算法補連筋——這是本專案 5dm 引擎在做的（拓撲不變量：
  鑿橋後殘腔＝0）。
- 若追求**方正式簡潔美學**，可提供一個「只連外框／淺層」的風格選項，
  容許深層 counter 保留（適合純展示、或料夠厚不會掉的材質）。

> R5 正是「切割風格」要參數化的核心軸之一（見 §4 的 `connect_depth`）。

## 3. 幾何判定法（規則 → 程式）

把 §2 規則落成可實作的判定步驟（對應 `exporters/stencil.py`）：

1. **光柵化**字形為 mask（True＝墨）。
2. **標記 counter**：`~mask & ~outside`（外部以泛洪自 mask 邊界決定）。
3. **偵測轉角**（R2）：counter 邊界迴圈 → RDP 簡化 → 方向變化 ≥45° 的
   頂點＝轉角候選（`_hole_corners`）。
4. **近牆軸向逃逸**（R3+R4）：每轉角試四軸方向，先驗「往內 2px 是墨」
   （近牆），再沿該向走到 outside，記錄穿牆路徑；取最短者。
5. **選橋**（R1 的量化）：最短穿牆優先（＝最薄的牆＝主幹以外的交叉
   筆）＋空間分隔（橋不擠一起）；橋數依 counter 大小自動（小孔 1、
   大孔 2，上限可設）。
6. **鑿橋**：沿逃逸路徑以方形筆頭（寬＝橋寬）挖白＝乾淨軸向缺口。
7. **驗證**：重數殘腔應為 0（R5 的「物理有效」判準）。

主幹 vs 交叉筆目前是**隱含**判定的（「最短穿牆＝穿過較薄的牆＝退掉
交叉筆、留下主幹」）。若未來要更忠實 R1，可加**顯式筆向分析**（見
§6 待強化）。

## 4. 「切割風格」抽象：參數化

一個**切割風格（cutting style）**＝一組規則參數。把下列參數集固定成
一個 struct/dict，就能定義多種風格、由 UI 下拉切換。建議欄位：

| 參數 | 意義 | 5dm 現值 | 方正式 | 備註 |
|---|---|---|---|---|
| `bridge_axis` | 缺口方向 | `axis`（四軸） | `axis` | 拉丁需 `curve_normal`（曲線切點）；另可 `stroke_aligned` |
| `bridge_at` | 斷點落點 | `corner`（轉角） | `corner`+`frame` | `midspan_ok=False` 恆守 |
| `near_wall_only` | 只穿近牆 | `True` | `True` | 關掉＝可穿腔到對側（不建議） |
| `bridge_width_mm` | 橋寬 | 2.0（可調） | ≈筆寬 | 脆料加寬 |
| `bridge_count_max` | 每孔橋數上限 | 4（自動取最少） | 1~2 | 大孔 2、小孔 1 |
| `connect_depth` | 連筋深度 | `full`（全連通、殘腔0） | `envelope`（只外框） | **R5 核心軸**（5eg 已接 registry；5ej envelope 深度 runtime 可調 `envelope_depth`＝連到第幾層、1..N） |
| `keep_primary` | 保主幹策略 | `thinnest_wall`（隱含） | `vertical_first`（顯式） | **5ei 已接 registry**（physical=thinnest_wall、envelope=vertical_first；垂直優先啟發式 ×BIAS，非骨架分析） |
| `frame_strategy` | 鏤空外框接法 | `nearest_spoke`（垂直輻條） | `nearest_spoke` | cutout 專用 |
| `min_feature_mm` | 去斑門檻 | 橋寬²/4 | — | 濾光柵碎點 |

**風格對照（示意）**：

- **風格「物理完整」（`physical`，預設）**：`connect_depth=full`——保證每個
  counter 都不掉料，適合真的要噴漆／雷切的字模。
- **風格「方正簡潔」（`envelope`，5eg 已加）**：`connect_depth=envelope`——
  只鑿 depth-1 孔（最外圈）、深層巢狀孔留島，最少斷點、最像手寫連筋字，
  適合展示或厚料（非物理完整）。（`keep_primary=vertical_first` 等更細的
  §4 參數尚未拉進 style struct，待需要時再加——YAGNI。）
- **風格「筆順對齊」（未來）**：`bridge_axis=stroke_aligned`——缺口順著
  筆畫方向，需筆向資料（見 §6）。

## 5. 加入新切割字體 / 新切割風格的步驟

**加字體**（純提供更好的字模底：均勻黑體最佳）：

1. 放字型檔（授權要能商用/打包；OFL 最佳，避開方正等商用字）。
2. 仿 `sources/noto_hei.py` 寫 `get_XXX_source()`、登 `zentangle.py`
   `SOURCE_REGISTRY`/`_LABELS`。
3. `render_fetch_fonts.sh`＋`render.yaml` 加佈署路徑。
4. `index.html` 的 `sc-source` 下拉加一項。
5. 測試：`test_XXX.py` 驗註冊＋字模拓撲有效（殘腔 0）。

**加切割風格**（同一字體、不同斷法）：

1. 把 §4 參數集固定成 `CUTTING_STYLES` registry（key→參數 dict）。
2. `carve_stencil_bridges` / `connect_cutout_components` 讀該 dict 的
   參數（目前這些參數多為函式引數或常數，需先集中成 style 物件）。
3. `stencil_geometry` 多收一個 `style` 參數、預設 `physical`。
4. `index.html` 加「切割風格」下拉；server endpoint 收 `style`。
5. 測試：每風格各驗其不變量（`full`→殘腔0；`envelope`→外框連通、
   容許深層殘腔；皆守 R2 中段不切）。

> 現況（5eg／0.14.211）：**已抽成 `CUTTING_STYLES` registry**（`stencil.py`），
> 且已有**兩個切割策略**：`physical`（`connect_depth="full"`＝全連派、殘腔 0）
> 與 `envelope`（`connect_depth="envelope"`＝只斷最外圈、深層 counter 留島、
> 非物理完整）。`stencil_geometry(style=...)`／`/api/stencil?style=` 帶風格、
> 未知風格回 422；UI（index.html）有「切割風格」下拉＋envelope 免責提示。
> registry seam＝5ef 純重構（QODA 選 A）；envelope 第二策略＝5eg（QODA 選 A：
> depth-1 射線法）。§4 其餘參數（bridge_axis/near_wall/keep_primary）目前在
> carve 函式內恆為 full 值，待需要它們的策略落地時再拉進 style struct（YAGNI）。

## 7. 多字型比較：風格與特徵歸納

實測五顆連筋/喷漆字型後最重要的結論：**「切割策略」與「筆形風格」
是兩條互相獨立的軸**。同一套連筋規則（§2 的 R1~R4）跨字型都成立，
變的只是筆畫長相。把這兩軸拆開，就是可切換切割風格系統的骨架。

### 7.1 軸一：切割策略（連筋深度／斷點落點）

決定**在哪裡斷、連到多深**。實測分兩派：

- **外框派（envelope-only）**——方正大黑連筋。只斷最外圈包圍＋淺層
  交接，深層巢狀 counter（國/圖/團 的內件）留成孤島。斷點最少、最
  好讀，但**非物理完整**（深層料會掉）。
- **全連派（full-connect）**——越卓大黑/隸書/等粗宋 三顆 喷漆版，
  對**每一個** counter 都斷開連通（口/日/田/国/回/**图** 全 0 殘腔，
  連圖的深層內件都連出）。物理有效字模。**＝本專案 5dm 引擎的策略。**

> 對照：方正「圖」留 4 殘腔、越卓「图」0 殘腔。我們的引擎與越卓同派
> （全連通、殘腔 0）；方正外框派可作為未來 `connect_depth=envelope`
> 的簡潔風格選項。

### 7.2 軸二：筆形風格（字系／筆畫美學，與切割策略正交）

決定**筆畫與其內縮端長什麼樣**。同樣是「保豎退橫、缺口貼交接」，
不同字系長相完全不同：

- **黑體（大黑）**：等粗、無襯線，缺口＝乾淨矩形。最俐落、最好切、
  可讀性最高——**字模首選**（竹米、方正、越卓大黑、邯鄲喷漆黑体皆此
  派）。其中**邯鄲喷漆黑体**特點是**單一字型同時涵蓋 CJK＋拉丁**
  （口日图 與 O/B/8 同一風格連筋），中英混排字模不必換字型；越卓大黑
  偏 CJK、邯鄲喷漆英文則是純拉丁（見 §7.3）。
- **隸書（越卓中隸書）**：保留**蠶頭燕尾、波磔、豎筆外弓**；連筋缺口
  一樣落在交接，但筆端是隸書的燕尾飛挑。裝飾性強、有書法味，細部
  比黑體易斷（燕尾尖），適合較厚料/裝飾用途。
- **等粗宋（越卓等粗宋）**：明體的**字腳/頓角襯線**保留，但**筆畫等粗**
  （非傳統宋體橫細豎粗）——這正是為字模改造的關鍵：靠等粗避開明體
  最怕的細橫。介於黑體俐落與明體典雅之間。
- **楷體（本專案教育部楷書）**：毛筆收筆帶尖、粗細對比大——**最不適合
  字模**（細尖處易斷，5dm 量測筆寬中位數僅 ≈6px）。列此僅為反例。

### 7.3 軸三：字系（CJK vs 拉丁），斷點幾何不同

- **CJK**：筆畫多正交（橫豎），斷點落在**正交交接角**，缺口**軸向
  對齊**（見 R2/R3）。
- **拉丁（邯鄲喷漆英文）**：字母多曲線，斷點落在**結構點**——
  圓形字母（O/Q/8）在**上下極點**斷開；碗形字母（B/D/P/R）在**碗與
  主幹的交接**斷開；A 在**頂點三角腔**開口。原則同 CJK（斷在結構點、
  保可讀、缺口≈筆寬），只是幾何從「軸向穿牆」變「曲線切點」。拉丁
  字模若要支援，逃逸方向不能只限四軸，要允許**沿法線切點**。

### 7.4 歸納：所有字模字型的共同不變量

不分字系/風格，五顆字型都守這四條（＝連筋規則的最小核）：

1. **斷在結構點**（交接／轉折／曲線極點），**絕不斷直筆中段**。
2. **保主幹**（豎筆/字幹全長）、**退交叉筆**（橫筆/碗）。
3. **缺口≈筆寬**、貼著結構點、不橫越整個腔體。
4. **全字仍可讀**——所有筆畫都在，只在交接處脫開。

差異只在兩個可切換旋鈕：**連筋深度**（外框派/全連派）× **筆形字型**
（黑/隸/宋/…，由選字型決定）。

### 7.5 對可切換架構的含意（重要）

本專案引擎是**在字型輪廓上光柵化＋補連筋**：

- **筆形風格軸「免費」**——使用者選哪顆字型，筆畫美學（黑/隸/宋）就
  跟著來，引擎不必另做；只要把隸書/等粗宋這類字型也接進 `SOURCE_
  REGISTRY`（同 noto_hei 作法），就多一種筆形風格可選。
- **引擎只需管切割策略軸**——即 §4 的 `connect_depth`（envelope/full）
  等參數。這大幅簡化「切割風格」系統：**風格 ≈（字型來源）×（切割
  策略 preset）**。
- 因此建議的 UI：字型下拉（筆形）＋切割風格下拉（策略 preset，如
  「物理完整」/「方正簡潔」），兩者自由組合。
