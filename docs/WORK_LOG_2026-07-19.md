## 5es：線上 503 修復——g0v bundle 改 JSONL 懶解析（0.14.223）

commit `3d64cf4`。5er 部署後抄經模式 503。

**根因**：bundle 單一大 JSON 全量解析 1,830 字實測膨脹 **305MB RSS**——
JSON 解析成 Python 物件有 10 倍級記憶體膨脹，Render free tier（512MB）
OOM → worker 被殺。功能驗證過了、目標環境記憶體天花板沒驗。

**修**：bundle 格式改 gzip JSONL（每行 hex<TAB>緊湊 JSON）；`_bundle()`
只存原始字串（實測 RSS 28MB、31 字離線 0.15s）、用到哪個字才
`json.loads` 哪行；threading.Lock 防 threadpool 併發首載雙倍瞬時記憶體；
**記憶體回歸鎖測試**：bundle 快取值必須是 str（預先解析即紅燈）。

**線上驗收 PASS**：抄經楷書 200（冷 14.2s→暖 3.9s、377KB gzip）、篆書
200；503 痊癒。附帶觀察：篆書暖請求仍 26s（骨架每請求重算）＝W2
lru_cache＋ETag 的最佳受益者。
