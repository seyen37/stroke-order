## 5fm：逐字手寫範字超出米字框——移除 1.4× 硬放大、改墨跡實框正規化（0.14.259）

commit `400d4d5`。實機回報：稿紙模式逐字手寫，「春」等滿框字範字超出米字格。

**根因（兩處疊加）**：`swDrawBase` 在 5fb 加了 `REF_SCALE = 1.4`，把範字置中放大
1.4×「任其裁切」——滿 EM 框的字（春）就溢出米字格。而稿紙/字帖那條建構器
`swBuildCellRefImg` 用固定 `viewBox 0 0 2048 2048`（整個 EM 框），四周留白因字
而異，才逼得要靠硬放大補「看起來太小」。

**修法（只動 modes/handwrite.js）**：把正規化下沉到建構器——`swBuildCellRefImg`
把該格 clone 暫掛回宿主 SVG 量 `getBBox()`，取墨跡實框的正方形＋8% 邊距，讓每
字墨跡固定佔 ~86%；`swDrawBase` 改 `drawImage(…, 0, 0, W, H)` 1:1 貼滿、`REF_SCALE`
整個移除；fillText fallback 字級一併去掉 1.4×。**同步修獨立 /handwriting 頁**
（`handwriting/reference.js` 的 `drawReference`）：舊法 `scale = min(w,h)/EM_SIZE`
把整個 EM 框鋪滿畫布→滿框字頂邊，改成同樣的墨跡長邊填滿 86% 置中，兩介面一致。

**驗證**：Playwright 截圖，彈窗＋獨立頁的「春」「一」皆填滿 ~86% 置中不溢框，無
page error。守門 `test_5fb_frontend_markers` 同步改斷言新不變式（REF_SCALE 已移除、
1:1 drawImage 在位、side*1.16 正規化在位）並加獨立頁守門。

## 工具鏈修正：收工檢查.bat 挑訊息檔靜默沿用舊訊息——加當日新鮮度守門（fail-open）

commit `5a1bd43`。5fm 首次跑收工檢查.bat 時 commit 訊息掛成 7/19 的「docs: 5fi～5fl
收官」，與實際 5fm 修正牛頭不對馬嘴。

**根因**：`.bat` 用 `for /f ... dir /b /o:n`（**檔名字典序**）挑
`docs\_commit_msg\*.txt` 的最後一個當「最新」訊息檔。這批沒有人建當班（07-22）訊息
檔，於是字典序最大的仍是 `2026-07-19_37.txt`，被原封套上。此坑 7/19（5er）就踩過、
當時僅在 WORK_LOG 留 note，結果復發。

**修法（只動 收工檢查.bat）**：挑檔後加 fail-open 新鮮度守門——用 PowerShell 取今天
日期，挑到的檔名不含今天日期就印 `STALE COMMIT MESSAGE -- NOT committing`、中止並
提示先建 `<今天>_NN.txt`；取不到日期則印 warning、跳過守門，**絕不誤擋正常提交**。
因 `YYYY-MM-DD` 字典序＝時間序，只要當班有放今天訊息檔它必為最大檔名並放行。發現
`docs/_commit_msg/` 是 gitignore（訊息檔本來就是本機草稿、不進版控），故零 repo churn。
下次執行即自帶實測（挑到當日檔、放行）。

## 5fn：抄經逐字手寫範字偏小——不同建構器漏改一輪，補墨跡實框正規化（0.14.260）

commit `2a9c0a3`。5fm 部署後回報：其他模式範字正常，但抄經模式的逐字手寫範字反而
偏小。

**根因**：抄經彈窗走的是**另一個建構器** `swBuildSutraRefImg`（非
`swBuildCellRefImg`）。它把視框裁到「整個字格 rect」，而抄經描紅字只佔字格約 6 成、
且字格非正方（含斷句/注音留白）；5fm 拿掉 `swDrawBase` 的 1.4× 後，抄經字就以字格
原比例 1:1 呈現→偏小。**一個病、兩個入口：改了共用下游（swDrawBase）漏清點上游
的全部建構器。**

**修法（只動 swBuildSutraRefImg）**：抄經字形層每字是一個 `<g transform>`、無
per-cell id，故以幾何命中——取「client 中心落在該格 rect 內」的字形群，量其 client
聯集框、經 `getScreenCTM()` 反矩陣換回 SVG user 座標，取正方＋8% 邊距為視框，讓墨跡
固定佔 ~86%，與 `swBuildCellRefImg` 同一比例。命中不到（罕見）才退回舊的整格裁切、
不致變空。動手前先在雲端渲染抄經預覽、檢視 DOM 結構（確認每字獨立 `<g>`、可幾何
隔離）＋原型量測（實測墨跡佔字格 0.56–0.74，證實偏小根因）才動工。

**驗證**：Playwright 實測抄經彈窗「觀」「在」皆填滿 ~86% 置中、與字帖/稿紙一致，無
page error。守門 `test_5eq_handwrite_ref_prefers_filled_layer_over_thick_skeleton`
同步改斷言新的 `_order` 優先序結構（填實層 reference→trace 在前、粗骨架殿後 break），
意圖（填實優先、骨架 fallback）不變。全量 1852 passed。

## 本輪事故與教訓（meta）

1. **守門測試鎖字面實作字串，三次咬紅**：`test_5fb`（鎖 `REF_SCALE = 1.4`）、
   `test_5eq`（鎖 `_filledIds = [...]`＋否定斷言）——保留意圖的重構把字串換掉就誤紅。
   每次都是「同批更新守門、commit 註明意圖不變」解掉。→ PRINCIPLES §66。
2. **裸 `git push` 誤入備份庫**：`main` 追蹤 `backup`（github-backup），首次裸 push
   進了備份庫、Render 來源 `origin` 沒更新。改 `git push -u origin main` 一次推 origin
   ＋把追蹤改回 origin，杜絕復發。
3. **橋接 `git status` 留 `.git/index.lock`**：device_bash 不能刪檔，git 清鎖失敗→
   殘留鎖會擋使用者原生 `git add`。以 `mv` 改名移開（留在 .git 內、不被 add-all 收）。
   教訓：橋接端少對連接資料夾跑會鎖 index 的 git 指令。
